# SqlRewriter: Harnessing Community Knowledge to Rewrite SQL Queries

**SqlRewriter** · ICDE 2026 (demo)

Read: [DOI](https://doi.org/10.1109/icde65706.2026.00326)

<p class="notice">An AI-written summary for orientation, not a source: check the original paper before relying on anything here.</p>

## In brief

- A community platform for contributing and sharing rewrite rules.
- Reuses QueryBooster's rule language and engine.
- A place where rules are collected; they are not formally verified.

## In plain words

Rewriting a SQL query into an equivalent one that can run faster matters, but the authors say rewrite know-how is scattered across blogs and forums and kept proprietary inside commercial optimizers (abstract, §I, PDF p. 1). This demo paper presents SqlRewriter, a public website where users contribute rewrite rules, apply community rules to their queries, and discuss them. A rule can be suggested from an example query pair, needs an administrator's approval before it becomes public, and can be rated, and revoked if issues arise (§I, PDF p. 1). It reports no experiments, just two usage stories. The authors call it, to their knowledge, "the first platform exclusively designed for sharing and innovating SQL query-rewrite knowledge" (§I, PDF p. 1).

## Background and terms

**Terms to know:** [query rewriting and rewrite rules](#/glossary/query-rewriting-and-rewrite-rules) · [query optimizer](#/glossary/query-optimizer) · [query equivalence](#/glossary/query-equivalence)

**The paper's own terms:**
- **rewrite rule**: a pattern and a rewrite, both SQL templates whose variables (written e.g. `<x1>` or `<<x9>>`) stand for tables, columns, expressions, predicates or subqueries (§II-B, Fig. 2, PDF p. 2; Fig. 6, PDF p. 4).
- **VarSQL**: the rule language, from the authors' QueryBooster, "a simple yet expressive rule language" (§III-A, PDF p. 2).
- **C1–C3**: the challenges the authors name: rule-quality control, user engagement and contribution, system reliability (§I, PDF p. 1).
- **private, pending, public**: a rule's states; editing or revocation makes a public rule private again (§III-A, PDF pp. 2–3).

**Builds on:**
- QueryBooster ([QueryBooster](#/papers/bai2023querybooster "QueryBooster: Improving SQL Performance Using Middleware Services for Human-Centered Query Rewriting (2023)"); refs. [5], [6]), the authors' rewriting middleware, whose rule language and rewriting engine SqlRewriter reuses (§I "Related Work", §II-B, PDF p. 2).
- Commercial tools EverSQL, SQLFlash and Keebo, which "use AI models to suggest rewritten queries" but keep their knowledge proprietary (§I "Related Work", PDF p. 1).
- Systems the paper says use machine learning to rewrite queries (Bao, Galo, LearnedRewrite [LearnedRewrite](#/papers/zhou2021learnedrewrite "A learned query rewrite system using Monte Carlo tree search (2021)")), and rule-discovery systems WeTune ([WeTune](#/papers/wang2022wetune "WeTune: Automatic Discovery and Verification of Query Rewrite Rules (2022)"), which searches the space of [logical plans](#/glossary/logical-plan)) and GRewriter ([GRewriter](#/papers/jiang2025grewriter "GRewriter: Practical Query Rewriting with Automatic Rule Set Expansion in GaussDB (2025)"), for cloud-database customers) (§I "Related Work", PDF pp. 1–2).
- LLM rewriters LLM-R2 ([LLM-R2](#/papers/li2024llmr2 "LLM-R2: A Large Language Model Enhanced Rule-Based Rewrite System for Boosting Query Efficiency (2024)")) and R-Bot ([R-Bot](#/papers/sun2024rbot "R-Bot: An LLM-based Query Rewrite System (2025)")), cited because their effectiveness "still fundamentally relies on the quality and volume of existing rewrite knowledge prepared by human experts" (§I, PDF p. 1).

## Problem and setting

- **Question:** how to build a platform where a community shares and develops rewrite rules (C1–C3, §I, PDF p. 1).
- **Motivation:** cited studies indicate that "solely depending on traditional database rewrites is inadequate for optimizing modern query workloads", e.g. queries generated by business-intelligence tools and object-relational mapping (ORM) libraries (§I, PDF p. 1).
- **What a rewrite must do:** produce "the same results" with "higher efficiency" (§I, PDF p. 1). Which SQL fragment or database is supported: not discussed; the Rule-C example of §III-B uses `DISTINCT ON` (one row per value of the listed columns) (Fig. 6, PDF p. 4).

## Approach

- **Architecture (§II-A, Fig. 1, PDF p. 2):** a frontend and a backend in a Kubernetes cluster (software that runs many copies of a service across machines); backend modules Query Rewriter, Rule Generator, Rule Manager, User Manager, Workflow Manager, Comment Manager. For C3 the frontend is React-based, the backend Python on Gunicorn (a Python web server), with a CI/CD pipeline (automatic testing and deployment) (§I, PDF p. 1).
- **Query Rewriter (§II-B, Fig. 2, PDF p. 2):** parses the query and the user's visible rules into syntax trees, applies rules with QueryBooster's engine until none matches, remembering the sequence to break cycles. Fig. 2's example removes a self-join.
- **Rule Generator (§II-B, PDF p. 2):** from before/after query pairs it tries turning tables, columns, expressions, predicates and subqueries into variables and "suggests the most general rewrite rule"; the user may edit it and submit it for approval.
- **Quality gates (C1, §I, PDF p. 1)**: suggestion from an example pair "to minimize human errors", approval before publication, thumbs-up/down ratings, revocation "if issues arise"; administrators can reject low-quality rules (§III-A, PDF p. 3).
- **Engagement (C2, §I, PDF p. 1):** rewriting one's own queries with community rules; public profiles with contributions, usage statistics, ratings and comments.

## Results

No experiments; design claims and two scenarios, worded as the authors':
- **Sharing (§III-A, Figs. 3–5, PDF pp. 2–3):** Alice's "Rule-A" turns a subquery into a join; Bob finds his query rewritten with it "indeed more efficient", adds "Rule-B: Distinct to Group-By", and Alice's query is rewritten with both. The system "ensures rule quality through automatic suggestions during rule creation and an approval workflow" (PDF p. 3).
- **Collaboration (§III-B, Figs. 6–7, PDF pp. 3–4):** Rule-C is approved "Because the rule is syntactically correct and captures a nontrivial optimization". On one test case Bob finds "the rewritten query returns more rows than the original" (PDF p. 3) and comments; Alice revises it "by introducing LEFT JOIN while keeping the DISTINCT ON structure", and after re-approval Bob finds it "now correctly preserves the semantics while maintaining performance benefits" (PDF p. 4).
- Users of PostgreSQL and MySQL rule plugins "can benefit from the rewrite knowledge collected in SqlRewriter" (§I "Related Work", PDF p. 2).
