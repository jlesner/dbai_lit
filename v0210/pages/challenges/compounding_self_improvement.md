# Self-improvement that compounds

> Self-improving LLM loops gain in the first round, then stall or regress. Make the gains compound: each round adds certified information, and each change is kept only if a certified, statistically controlled check shows it doesn't regress.

**Source:** added. It joins the compounding claim of [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop) to the measurement challenge of [Comparing LLM methods under noise](#/challenges/method_comparison_under_noise).

## Challenge
An improvement loop changes an LLM system round after round: its prompts, memory, skills or harness. The loops in the summaries that run several rounds mostly show one shape: most of the gain comes in the first round, then it stalls or falls.
- [Self-play](#/glossary/self-play) [text-to-SQL](#/glossary/text-to-sql) with no human pairs gains mostly in its first iteration, and "no sequence compounds" (per [SQL-Zero](#/papers/pedrozo2026sqlzero "SQL-Zero: Self-Evolving Text-to-SQL (2026)")'s summary § Results, unchecked).
- Self-training against a free, exact verifier gains for two rounds but never accelerates, and the base model given more tries still beats the trained one (per [Teacher-Free Self-Training Amplifies but…](#/papers/strozzi2026selftraining "Teacher-Free Self-Training Amplifies but Does Not Compound: A Pass@$K$ Crossover on a Free-Verifier Domain (2026)")'s summary § Results, unchecked).
- Self-improvement filtered by the model's own verification vanishes within two or three rounds as diversity falls (per [Mind the Gap](#/papers/song2024mindgap "Mind the Gap: Examining the Self-Improvement Capabilities of Large Language Models (2025)")'s summary § Results, unchecked).
- Self-play fine-tuning on text-to-SQL peaks after one iteration (per [ExSPIN](#/papers/yan2025exspin "ExSPIN: Explicit Feedback-Based Self-Play Fine-Tuning for Text-to-SQL Parsing (2025)")'s summary § Results, unchecked).
- Puzzles a code model writes and solves, filtered by an interpreter, gave "a large benefit from the first iteration and small benefit from the second", read by its authors as a possible plateau ([Language Models Can Teach…](#/papers/haluptzok2022teach "Language Models Can Teach Themselves to Program Better (2022)") §4.3, Fig. 7; §5).

These five train weights. APE's iterative search shows "diminishing returns" as prompt quality "seems to stabilize after three rounds" ([APE](#/papers/zhou2022ape "Large Language Models Are Human-Level Prompt Engineers (2023)") §5.3); Promptbreeder keeps a diverse population; in one shown run training fitness "continues to increase throughout the run" ([Promptbreeder](#/papers/fernando2023promptbreeder "Promptbreeder: Self-Referential Self-Improvement Via Prompt Evolution (2023)") §1, §5, App. B), though runs stopped once it "appeared to plateau" (App. J.2).

The loops that keep gaining share three things in the summaries: a precise check on what is kept, a gate against regressions, and new information each round.
- In self-distillation, held-out gain grows with the checker's precision, rejecting correct outputs costs little, and with a precise gate three rounds compound (per [The Verifier is the Curriculum](#/papers/zhou2026curriculum "The Verifier is the Curriculum: Precision Sets the Return on Search in Code Self-Distillation (2026)")'s summary § Results, unchecked; weights trained, one engine).
- Re-optimizing an agent on new tasks, an optimizer that rejects any change breaking an already-solved task averaged highest, while a GEPA-optimized prompt of lessons first fell below the unoptimized agent (per [Do Agent Optimizers Compound?](#/papers/wang2026compound "Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0 (2026)")'s summary § Results, unchecked).
- Harness edits kept only when the targeted tasks recover and nothing regresses never fell below the unedited harness (per [HarnessLens ("Verify Smarter](#/papers/xu2026harnesslens "Verify Smarter, Evolve Further: Efficient Harness Evolution through Behavior-Aware Verification (2026)")'s summary § Results, unchecked; its attribution step is an LLM judgment).
- A proof agent that rewrites its own prompts, tools and workflow against a fixed checker, practising on a set that retires solved problems for harder ones, gained more than on a fixed set (per [Self-Modifying Lean Proof Agents](#/papers/li2026selfmodifying "Self-Modifying Lean Proof Agents with Verifier-Grounded Benchmark Coevolution (2026)")'s summary § Results, unchecked; one run).
- In theorem proving, its authors say [expert iteration](#/glossary/expert-iteration) "plateaus" because correct proofs of the unproved statements are too rare to train on, while STP's self-generated conjectures, proved more often, give "more training signals, leading to better scaling" ([STP](#/papers/dong2025stp "STP: Self-play LLM Theorem Provers with Iterative Conjecturing and Proving (2025)") §4.4; weights trained).
- New verified examples that target each failure pattern raise the gains of three prompt optimizers (per [FORGE](#/papers/yuan2026forge "Failure-Guided Co-Evolution of Prompts and Training Data (2026)")'s summary § Results, unchecked; its verifier is an LLM); in our reading, new information of this kind is one way to avoid the stall.

The challenge is to make compounding the rule in prompt space: every round adds certified information (counterexamples, harder items), and every change is kept only when a certified, statistically controlled test shows it doesn't regress.

## Why it matters
- **Compounding is the difference between a method and a system that keeps getting better.** A loop that gains once is one more method improvement; a loop whose per-round gain stays above zero keeps improving a system with no human labels and no weight training (our reasoning).
- **Every self-improvement loop needs the gate.** Reusing one evaluation set for keep-or-reject decisions promotes false improvements; a rule that returns only decisions to the proposer and budgets its error over all decision histories made none (per [Which Self-Improvements Should We…](#/papers/sun2026reuse "Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks (2026)")'s summary § Results, unchecked; one tabular task). Telling real improvement from gamed improvement inside a self-evolving loop is unsolved and costly (per [HackProbe](#/papers/yang2026hackprobe "Harness-agnostic detection and immunization of reward hacking in self-evolving language models (2026)")'s summary § Results, unchecked). Noise is [Comparing LLM methods under noise](#/challenges/method_comparison_under_noise)'s side of this, bias is [Weak checkers get exploited](#/challenges/weak_checker_exploitation)'s.
- **Prompt-space learning works when it is checked.** A frozen model that keeps a tip only when the tip then solves its problem beats GEPA, RL and memory baselines (per [CORE (Contrastive Reflection)](#/papers/nasvytis2026core "CORE: Contrastive Reflection Enables Rapid Improvements in Reasoning (2026)")'s summary § Results, unchecked); stored verified corrections raise text-to-SQL accuracy while stored unchecked majority-vote answers fall below no memory (per [Measuring Crystallization in Text-to-SQL](#/papers/wang2026crystallization "From Test-Time Scaling to Reusable Memory: Measuring Crystallization in Text-to-SQL (2026)")'s summary § Results, unchecked); context optimization with an insight memory matches RL on one model (per [MEMO](#/papers/xie2026memo "MEMO: Memory-Augmented Model Context Optimization for Robust Multi-Turn Multi-Agent LLM Games (2026)")'s summary § Results, unchecked). In SQL, SQLGovernor's rule base, extended by an LLM from failed queries and admitted by experts, raises EX on BIRD dev over stages of self-learning ([SQLGovernor (Tencent)](#/papers/jiang2025sqlgovernor "SQLGovernor: An LLM-powered SQL Toolkit for Real World Application (2025)") §4.3, §6.4.3, Fig. 7); the paper doesn't say whether the consumed data excludes the evaluated queries. The admission check is [Can a memory across problems be checked before it is reused?](#/challenges/verified_memory).
- **SQL supplies the [certificates](#/glossary/certificate).** A counterexample validated by execution, or a proof, gives a precise gate and new information each round.

**Size of the gain:** step change, measured as held-out certified accuracy per round of an improvement loop: compounding means the per-round gain stays above zero past round three, against the one-round plateau the summaries report. If it holds, a system keeps improving without labels or weight training. This is our estimate, and contested: these five loops (four per summaries) report no compounding, and most positive cases train weights.

## Verifiable signal
Held-out certified accuracy after each round, on items never used for selection, with the keep-or-reject rule fixed in advance; compared with an ungated loop and a self-judged one, over five or more rounds and several seeds. The loop compounds when the per-round gain stays above zero, beyond the test's error, past round three. The gate is measured by its false-promotion rate on changes known to be null. In SQL the items and the gate's verdicts are certified by executing counterexamples and by proofs; the statistics are [Comparing LLM methods under noise](#/challenges/method_comparison_under_noise) § Verifiable signal.
