# Can SQL equivalence checkers be trusted?

> Provers, bounded checkers and the harnesses around them certify wrong *equivalent* verdicts, and the benchmarks they are tested on can't show it.

## Challenge
A proof is the only [certificate](#/glossary/certificate) for *equivalent* outside the fragments where a finite test family decides it ([Query equivalence: prove or refute](#/challenges/query_equivalence) § Verifiable signal). But a prover's answer is only as sound as every layer under it, and the collection holds failures at each one:
- **Reported by others.** The cvc5 authors found false *equivalent* verdicts in SQLSolver and SPES, which their developers "acknowledged … as an error" ([Verifying SQL Queries using…](#/papers/mohamed2024cvc5sql "Verifying SQL Queries using Theories of Tables and Relations (2024)") §5); the Argus authors reported bugs in SQLSolver and QED, among them a wrong equivalence proof ([Argus](#/papers/mang2025oracles "Automated Discovery of Test Oracles for Database Management Systems Using LLMs (2025)") §8); the QED authors report a SPES rule that "unsoundly rewrites" a left join on TRUE into a cross join, there making SPES miss an equivalence ([QED](#/papers/wang2024qed "QED: A Powerful Query Equivalence Decider for SQL (2024)") §6.3.1); the ParSEval authors say formal verification-based approaches "ignore projection" and called pairs differing in projected columns equivalent, results they "manually fixed" without naming the tool ([ParSEval](#/papers/chen2025parseval "ParSEval: Plan-aware Test Database Generation for SQL Equivalence Evaluation (2025)") §5.3, PDF p. 11).
- **Rule application.** A rule proved correct can still be applied where it is wrong: WeTune's released rewriter skips its rules' `NotNull` conditions, and an optimizer used as a checker takes its rules as "known to be sound" ([QO-Verify](#/papers/narasayya2026qoverify "Leveraging Query Optimizers to Verify the Soundness of LLM-based Query Rewrites for Real-World Workloads, and More! (2026)") §1) while VeriEQL's counterexamples exposed confirmed Calcite rule bugs ([VeriEQL](#/papers/he2024verieql "VeriEQL: Bounded Equivalence Verification for Complex SQL Queries with Integrity Constraints (2024)"); [Refuting faulty rewrite rules](#/challenges/faulty_rewrite_rules)). RuleScript's QED-verified rules run through an adapter and interpreter its authors call "trusted components", not verified ([RuleScript](#/papers/pan2026rulescript "An Extensible and Verifiable Language for Query Rewrite Rules (2026)") §7.2; its §2 claims "sound" execution).
- **Semantics vs engine.** A checker sound for its [formal semantics](#/glossary/formal-semantics) is wrong where the semantics is: one that ignores NULLs can "prove [query equivalences](#/glossary/query-equivalence) that are unsound in realistic databases" ([A Formalization of SQL with Nulls](#/papers/ricciotti2020nulls "A Formalization of SQL with Nulls (2022)") abstract). Guagliardo and Libkin hold that "the only way to convince oneself" a semantics models SQL is experimental ([A Formal Semantics of SQL Queries](#/papers/guagliardo2017semantics "A formal semantics of SQL queries, its validation, and applications (2017)") §1, PDF p. 2); the Coq semantics with NULLs of [A Formalization of SQL with Nulls](#/papers/ricciotti2020nulls "A Formalization of SQL with Nulls (2022)") leans on their tests and names the "formalization gap" left (§9, PDF p. 30), and its own well-formedness and evaluation rules disagree on [LATERAL](#/glossary/lateral). The numeric domain is part of the semantics: some equivalences of aggregate queries hold over the integers but not over the rationals ([Deciding Equivalences among Conjunctive…](#/papers/cohen2007aggregate "Deciding Equivalences among Conjunctive Aggregate Queries (2007)") PDF p. 7).
- **Harness and front end.** Kernel-checked proofs are only as sound as the code that builds the goal and screens the proof: Logos's SQLGlot–Calcite–Rust front end lowers SQL outside the kernel ([Logos](#/papers/ke2026logos "Logos: Certified Order-Sensitive SQL Rewrites with Mechanized Semantics and LLM Guidance (2026)") §4), and its authors say SQLGlot translation can change a benchmark case's meaning (§5.4); DeepSeek-Prover-V2's extra solves came from a Lean bug ([DeepSeek-Prover-V2](#/papers/ren2025deepseekproverv2 "DeepSeek-Prover-V2: Advancing Formal Mathematical Reasoning via Reinforcement Learning for Subgoal Decomposition (2025)"); [Weak checkers get exploited](#/challenges/weak_checker_exploitation)); Aria's agent, when it edits the proof file, "can satisfy the verifier while silently dropping or weakening the target lemma" ([Harnessing Code Agents for…](#/papers/kan2026aria "Harnessing Code Agents for Automatic Software Verification (2026)") §8); Quarry's released screen lets `Admitted.` through; UDP's authors name its parser, converter and axioms as its trusted code base ([UDP](#/papers/chu2018udp "Axiomatic foundations and algorithms for deciding semantic equivalences of SQL queries (2018)") §6.1), and the paper's printed GROUP BY de-sugaring is wrong under [bag semantics](#/glossary/bag-semantics) (§3.2).

## Why it matters
- **Every certified label rests on it.** [Benchmarks with checkable ground truth](#/challenges/checkable_benchmark_ground_truth), [Discovering new rewrite rules](#/challenges/rewrite_rule_discovery) and the [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop) turn a checker's *equivalent* into a label, an admitted rule or a reward; GaussDB's GRewriter treats a rule as correct once SQLSolver proves its representative concrete pairs equivalent ([GRewriter](#/papers/jiang2025grewriter "GRewriter: Practical Query Rewriting with Automatic Rule Set Expansion in GaussDB (2025)") §6.2, Thm. 6.1; [Discovering new rewrite rules](#/challenges/rewrite_rule_discovery) § Verifiable signal). An unsound checker poisons all three, and search and training find its holes ([Weak checkers get exploited](#/challenges/weak_checker_exploitation)).
- **The benchmarks can't see it.** SPES's suite "contains 232 semantically equivalent query pairs" ([SPES](#/papers/zhou2020spes "SPES: A Symbolic Approach to Proving Query Equivalence Under Bag Semantics (2022)") §7.2) and SQLSolver's evaluation counts "equivalent query pairs" ([SQLSolver](#/papers/ding2023sqlsolver "Proving Query Equivalence Using Linear Integer Arithmetic (2023)") PDF p. 21), so a false proof scores as a success; QO-Verify asserts "It does not produce any false positives" ([QO-Verify](#/papers/narasayya2026qoverify "Leveraging Query Optimizers to Verify the Soundness of LLM-based Query Rewrites for Real-World Workloads, and More! (2026)") §2.2) and is run only on rewrites whose results already matched (§4.2–4.3). The Argus authors say such bugs are common in prototypes "validated only on small benchmarks" ([Argus](#/papers/mang2025oracles "Automated Discovery of Test Oracles for Database Management Systems Using LLMs (2025)") §8).
- **The method carries over.** Every verifier-anchored system, in code and mathematics too, trusts a checker; a way to certify the checker's mistakes is general (our reasoning). In code, stronger tests or a human audit expose wrong programs that unit tests accept ([The Limits of Inference…](#/papers/stroebl2024resampling "The Limits of Inference Scaling Through Resampling (2024)") §3; [When the Reward Suite Is Leaky](#/papers/zhang2026leaky "When the Reward Suite Is Leaky: A Preregistered Causal Contrast of Natural Verifier False Positives in RLVR (2026)") abstract).

**Size of the gain:** enabler, measured as the number of certified soundness bugs found in the checkers that label pairs and admit rules. Each one found removes a class of false labels from [Benchmarks with checkable ground truth](#/challenges/checkable_benchmark_ground_truth) and of false rules from [Discovering new rewrite rules](#/challenges/rewrite_rule_discovery), and lets the loop's reward be trusted. This is our estimate.

## Verifiable signal
Cheap and certain in one direction: an *equivalent* verdict on a pair for which a validated [counterexample database](#/glossary/counterexample-database) exists (run both queries in a real engine; deterministic, no error or timeout, [Equivalence of nondeterministic queries](#/challenges/nondeterministic_equivalence)) is a certified soundness bug in the checker or in the layer that produced its goal. For a rule, one counterexample instance certifies a bug in the rule and in its verifier. For a [proof assistant](#/glossary/proof-assistant), accepted proofs of both a statement and its negation certify a harness bug (our reasoning).
