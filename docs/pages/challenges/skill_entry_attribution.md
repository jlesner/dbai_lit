# Which entries of a learned skill help

> The engine judges whole answers, but a skill holds many entries; measure each entry's effect on the engine's verdicts, per task family and size.

<p class="tags"><a class="tag sub" href="#/tags/promptopt-context">promptopt-context</a></p>

**Source:** added ([CORE (Contrastive Reflection)](#/papers/nasvytis2026core "CORE: Contrastive Reflection Enables Rapid Improvements in Reasoning (2026)") §6).

## Challenge
A measured effect on engine verdicts for each entry of a skill document and each example in its library, per task family and size, kept current as entries are added. ASSAY already measures each skill's effect on task success by random masking ([Not All Skills Help](#/papers/wang2026assay "Not All Skills Help: Measuring and Repairing Agent Knowledge (2026)") §2.1, §3.1); what it leaves open is a sound check, a view per family and size, and keeping the measure current (ours; § What's known). The loop keeps or prunes entries on whole-answer verdicts, so it can't tell an entry that helps from one that is never used or one that breaks other families (ours).

## What's known
  - ASSAY masks skills at random and takes each skill's effect on each development task as the difference in mean success with and without it ([Not All Skills Help](#/papers/wang2026assay "Not All Skills Help: Measuring and Repairing Agent Knowledge (2026)") §2.1), on AppWorld and τ-bench, computed once per base model (§2.1, §3.1).
  - SkillSandbox runs each skill with and without it on tasks built around the situation it was written for, admitting it only on a positive gain ([SkillSandbox](#/papers/kim2026skillsandbox "SkillSandbox: Skill Verification via Dynamic Scenario Synthesis (2026)") §3.3; App. B), on ALFWorld and WebShop (§1).
  - In LLM programs, one global score blames every module at once, and a prompted LLM judge ranks a component's outputs "closer to random guessing" (LLM program optimization).
  - SEPO records the training examples each prompt edit newly fixed and newly broke, for later edits on its branch ([SEPO](#/papers/ma2026sepo "SEPO: Evidence-Grounded Prompt Optimization via Structural Editing (2026)") §3.3).
  - MIRA groups the edits of a SQL repair by dependency and reverts each group alone, keeping it only when a semantic judge accepts it ([MIRA (Memory-Item Reuse and Adaptation)](#/papers/liu2026mira "MIRA: Evidence-Verified Repair Memory for Text-to-SQL Correction (2026)") §3.2.2; an LLM, our reading of §4.1).
  - PCO splits a critic LLM's verdict so that each part updates only the piece it blames, and keeps a running success rate per codebook entry ([Prompt Codebooks (PCO)](#/papers/nath2026codebooks "Prompt Codebooks: Discrete Compositional Optimization for Language Model Instruction Refinement (2026)") §3.5–3.6).
  - Exemplar-Curation scores each stored [trajectory](#/glossary/trajectory-agent) by the success of the tasks it was retrieved for ([Self-Generated In-Context Examples Improve…](#/papers/sarukkai2025selfgenerated "Self-Generated In-Context Examples Improve LLM Agents for Sequential Decision-Making Tasks (2025)") §5.3); MEMCoder's error attributor, an LLM, judges which API caused a failure ([Learning from Execution](#/papers/li2026privatelibrary "Learning from Execution: Self-Evolving Memory for Private-Library Code Generation (2026)") §IV-D).
  - ReplayLens's authors cite CAMEO and Causal Agent Replay, neither listed, as measuring an entry's or step's contribution; ReplayLens itself changes how outcomes are assigned to actions or placed ([ReplayLens](#/papers/xu2026replaylens "ReplayLens: Auditing Agents' Use of Outcomes (2026)") §2).
- CORE gives every retrieved insight the same outcome, leaving "finer-grained credit assignment among multiple insights unresolved" ([CORE (Contrastive Reflection)](#/papers/nasvytis2026core "CORE: Contrastive Reflection Enables Rapid Improvements in Reasoning (2026)") §6).
- Open (ours): no listed work measures each entry's effect on verdicts from a sound check, per family and size, kept current as entries are added. ASSAY and SkillSandbox score task success, not [certificates](#/glossary/certificate). ASSAY's cells are per development task, carried to test tasks by embedding neighbours ([Not All Skills Help](#/papers/wang2026assay "Not All Skills Help: Measuring and Repairing Agent Knowledge (2026)") §2.1, §2.3), with no grouping by family or size (ours); it assumes a fixed library, and its authors say added skills would need incremental attribution updates (App. A.3); its skills are short rules, heuristics and templates (§1), so examples go unmeasured (ours).

## Why it matters
- **A net gain can hide entries that break whole families** (ours), and an edit that passes a gate on its own family can lower others (skill_scope_interference).
- **Pruning needs it:** a library whose entries are credited equally ([CORE (Contrastive Reflection)](#/papers/nasvytis2026core "CORE: Contrastive Reflection Enables Rapid Improvements in Reasoning (2026)") §6) or by an LLM's blame can only be pruned blindly (ours), and a library credited but never used reads as learning (engine_judged_skill_loop § What would answer it, Diagnostic).

**Size of the gain:** enabler, our estimate. The quantity it lifts is the one [Self-improvement that compounds](#/challenges/compounding_self_improvement) measures, held-out certified accuracy per round, here after pruning entries by measured effect against pruning by LLM blame. The reason: a loop that can't tell which entries help can only keep or drop a skill whole.

## Why it's hard
- **Entries interact:** on Terminal-Bench 2, an evolved harness's positive single-component gains, each component swapped alone into the seed, summed to more than the full system's; its authors leave "interaction-aware evolution to future work" ([Agentic Harness Engineering (AHE)](#/papers/lin2026ahe "Agentic Harness Engineering: Observability-Driven Automatic Evolution of Coding-Agent Harnesses (2026)") §4.4.1).
- **Per-entry tests are underpowered:** at the mask count ASSAY ran (GPT-5.1), per-cell [permutation tests](#/glossary/permutation-test) have little power, and its descriptive threshold "cannot distinguish real heterogeneity from noise at the single-skill level" ([Not All Skills Help](#/papers/wang2026assay "Not All Skills Help: Measuring and Repairing Agent Knowledge (2026)") App. K.1), flagging about every skill with no effect (Tab. 9).
- **An entry can help and harm at once:** reflection fuses noise-induced and useful clauses into one rule, so removal "would require a granularity down to the clause, with provenance retained per clause", RSE-Bench's authors say ([When Non-Adversarial Noise Hurts Learning](#/papers/yu2026rsebench "When Non-Adversarial Noise Hurts Learning: Benchmarking Skill Self-Evolution in Agents (2026)") App. G.4); the validation they study judges each update whole (§5.4).
- **Retrieval isn't use:** retrieval counts measure "exposure to a skill, not whether it was applied" ([ChipMEM](#/papers/alrabah2026chipmem "ChipMEM: Verification-Grounded Memory for EDA Agents (2026)") App. A.2.2).
- **An edit's damage shows late:** [Checking a memory across problems before it is reused](#/challenges/verified_memory) § What's known.

## Verifiable signal
Each entry's effect is ASSAY's estimator ([Not All Skills Help](#/papers/wang2026assay "Not All Skills Help: Measuring and Repairing Agent Knowledge (2026)") §2.1, Eq. 1) with engine verdicts on fresh gym tasks in place of task success: on each task, the mean verdict over random masks that include the entry minus the mean over those that don't, so that the other entries are averaged over (ours). A pass is certified on the families whose engine verdict decides correctness. The design's cost is power: a per-cell test, one entry on one task, needs more masks than ASSAY ran to detect the effect size its authors tested, by their power analysis (App. K.1, Tab. 9; § Why it's hard).

**Named attack (ours):** ASSAY-style masking in a DSL gym, where a pass is certified, per family and size and kept current as entries arrive; it measures how many keep and prune decisions made from benchmark checks the engine's verdicts overturn.
