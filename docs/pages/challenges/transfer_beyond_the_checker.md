# Gains made against a checker, carried beyond it

> Do gains a model makes against a program checker, in its weights or with its weights fixed (prompts, skills, memory), carry over to tasks the checker can't check: near, the same DSL on a task only examples check, such as writing a program from English; far, open-ended work in other domains?

## Challenge
Training against a checker pays inside the checker's reach; how far it pays outside is not settled. Learn against a sound checker on certified DSL tasks (output prediction, counterexamples, inputs built for a wanted result), with the weights fixed and with weight training as the baseline, and measure whether the gain reaches evidence-only tasks in the same DSL (programs from examples or from English) and tasks no program checks, with controls showing that the checker's verdicts caused it.

## What's known
Several abstracts claim more than their papers show. Filed work, by where the gain was made and where it was measured:
- SFT on generated, scored problems raised every held-out reasoning benchmark at 3B in the main comparison, not in every setting ([Reasoning Core](#/papers/sileo2026reasoningcore "Reasoning Core: Designing Broad Procedural Data for Completion-Supervised Reasoning Training (2026)") §5.1, Tab. 2). Against these, a 1.7B model trained on validated plans and then by RL on the validator's verdicts produced no valid plan on held-out planning domains; the RL "does not improve cross-domain generalization" ([On the Generalization Gap in LLM Planning](#/papers/belcamino2026generalizationgap "On the Generalization Gap in LLM Planning: Tests and Verifier-Reward RL (2026)") abstract, §6.2; single runs). Every target here is scored by a key (ours).
- **Weights, to keyed tasks outside reasoning:** from one base and the same math problems, RL kept non-reasoning scores (conversation, instruction following, hallucination detection) above the base, while SFT on a larger model's traces lowered them ([Does Math Reasoning Improve…](#/papers/huan2025mathtransfer "Does Math Reasoning Improve General LLM Capabilities? Understanding Transferability of LLM Reasoning (2025)") §2.2, Tab. 1, App. A.3.2); in its ablation, on-policy training transferred better than off-policy training to other-reasoning and non-reasoning tasks, for SFT as well as RL, while off-policy training scored higher on math (§5.2, Tab. 4), and the authors name the sampling distribution the most important factor (§6). Its audit's "consistently" fails row by row.
- **Weights, to open-ended tasks:** the RLMT authors state that long chain of thought learned through RLVR "does not generalize well to open-ended tasks" ([RLMT ("Language Models that Think](#/papers/bhaskar2025rlmt "Language Models that Think, Chat Better (2026)") abstract), from other groups' models trained on other data, several of them distilled rather than RL-trained; its one comparison from the same checkpoints, math-only against chat-only RL, is one run each (App.
- **Weights, near transfer in code, graphs and SQL:** SemCoder trains execution reasoning together with code generation but has no matched run without the execution data (a model trained on its code data alone appears only in another table, with no stated settings), so the effect on generation isn't isolated ([SemCoder](#/papers/ding2024semcoder "SemCoder: Training Code Language Models with Comprehensive Semantics Reasoning (2024)") §6.2, App. F, Tab. 8). Sparks reports [text-to-SQL](#/glossary/text-to-sql) training raising table question answering, but its rewards compare query text with the reference rather than run queries, and an LLM grades both tasks ([Sparks of Tabular Reasoning](#/papers/stoisser2025sparks "Sparks of Tabular Reasoning via Text2SQL Reinforcement Learning (2025)") §3.2.2, §4.1); STRuCT-LLM reports "slight positive transfer" between SQL and Cypher, again with rewards that run no query ([STRuCT-LLM](#/papers/stoisser2025structllm "STRuCT-LLM: Unifying Tabular and Graph Reasoning with Reinforcement Learning for Semantic Parsing (2025)") §4.4). Training on a task's graph or code form alone "does not reliably generalize" to the same task in English; RL on the graph form, then on English, beat English-only RL at equal steps, but not under SFT ([Can Large Language Models…](#/papers/lin2026procedures "Can Large Language Models Generalize Procedures Across Representations? (2026)") abstract, §3.2, §4.1).
- **Easy to hard under the same kind of check:** supervision on easy items carries to hard ones, through in-context examples as well as fine-tuning ([The Unreasonable Effectiveness of…](#/papers/hase2024easydata "The Unreasonable Effectiveness of Easy Training Data for Hard Tasks (2024)") §1; some settings fall below its stated range), and from re-ranking gains the Easy-to-Hard authors conclude that [reward models](#/glossary/reward-model) trained on easy math problems generalize to hard ones better than generators ([Easy-to-Hard Generalization](#/papers/sun2024easytohard "Easy-to-Hard Generalization: Scalable Alignment Beyond Human Supervision (2024)") §4.2.1; Learned verifiers).
- **Weights fixed:** SynTra tunes a system-message postfix on a task whose hallucinations a program counts, and reports less hallucination on summarization and question answering that no program checks ([SynTra (Synthetic Transfer)](#/papers/jones2023syntra "Teaching Language Models to Hallucinate Less with Synthetic Tasks (2023)") abstract, §3.2), though not on every task–model pair; the postfix is continuous embeddings tuned by gradient, not text (§2.3), and GPT-4 with an unpublished prompt scores the targets (App. B.5). For text, the listed results are narrower: memories pooled from other coding benchmarks raised an agent's average ([Memory Transfer Learning (MTL](#/papers/kim2026memorytransfer "Memory Transfer Learning: How Memories are Transferred Across Domains in Coding Agents (2026)") abstract), and one skill evolved on a search benchmark raised another ([EvoSkill](#/papers/alzubi2026evoskill "EvoSkill: Automated Skill Discovery for Multi-Agent Systems (2026)") §3.3; "broader investigation across more diverse task pairs is needed", §4.3). Neither learned against a program checker: the memories come from runs an LLM judge labels ([Memory Transfer Learning (MTL](#/papers/kim2026memorytransfer "Memory Transfer Learning: How Memories are Transferred Across Domains in Coding Agents (2026)") §3.1.1), and skills by a score on labelled questions (Memory across problems). Scored on its optimization tasks together with new tasks of the same benchmark, GEPA's optimized agent fell below the unoptimized baseline while two other optimizers stayed above it ([Do Agent Optimizers Compound?](#/papers/wang2026compound "Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0 (2026)") §6.2, Tab. 1), and a GEPA prompt's superiority "does not reliably transfer to other models" ([Beyond the Answer](#/papers/pandey2026beyondanswer "Beyond the Answer: Decoding the Behavior of LLMs as Scientific Reasoners (2026)") §4.1; no item counts or held-out split stated).

## Why it matters
- **It tests the fixed-weights attack where the evidence is thinnest:** the user prefers fixed weights and compact open models, and the listed frozen-weight transfer results in § What's known are on 13B models with a continuous prompt ([SynTra (Synthetic Transfer)](#/papers/jones2023syntra "Teaching Language Models to Hallucinate Less with Synthetic Tasks (2023)") App. B.1) or on API and frontier-scale models ([Memory Transfer Learning (MTL](#/papers/kim2026memorytransfer "Memory Transfer Learning: How Memories are Transferred Across Domains in Coding Agents (2026)") §3.2.2, §4.1.1, [EvoSkill](#/papers/alzubi2026evoskill "EvoSkill: Automated Skill Discovery for Multi-Agent Systems (2026)") §3.1.2, [Do Agent Optimizers Compound?](#/papers/wang2026compound "Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0 (2026)") §4.1).
- **A DSL makes the near half measurable:** near targets keep an engine check, so a transfer claim can rest on certified failures rather than on a judge (ours; § Verifiable signal).

**Size of the gain:** enabler. It is measured on held-out success on the evidence-only tasks of [Prompt-space self-play judged by an engine](#/challenges/prompt_space_self_play) and [Checking text-to-SQL against intent](#/challenges/text_to_sql_verification), lifted by learning on certified tasks. A gain that carries lets the gym's certified task families train the evidence-only ones; one that doesn't bounds what the research path can claim to its certified tasks. Our estimate.

## Why it's hard
- **Far targets lose the [certificate](#/glossary/certificate):** open-ended work is scored by an LLM judge or by people ([SynTra (Synthetic Transfer)](#/papers/jones2023syntra "Teaching Language Models to Hallucinate Less with Synthetic Tasks (2023)") App. B.5; [RLMT ("Language Models that Think](#/papers/bhaskar2025rlmt "Language Models that Think, Chat Better (2026)") App. D.1), so far transfer is measured with evidence only (LLM as judge).
- **The arms differ in more than the training signal:** Huan et al.'s audit sets RL models trained from base models against SFT models trained mostly from instruction-tuned ones, and its controlled SFT arm imitates a larger model's traces; RLMT's far-transfer claim compares other groups' models.
- **The checker may not be what helped:** CodeI/O keeps responses the check rejects; dropping them did no better than a random half of the data ([CodeI/O](#/papers/li2025codeio "CodeI/O: Condensing Reasoning Patterns via Code Input-Output Prediction (2025)") §4.1, Tab. 2; [Distillation](#/glossary/distillation) into compact models), and Sparks' rewards never run a query. In a skill loop on text-to-SQL, an evolved grader kept the full lift of a loop given ground truth; its authors credit this to its only picking which failures feed the skill, citing near-chance agreement from other runs ([Who Verifies the Verifier?…](#/papers/zhang2026whoverifies "Who Verifies the Verifier? Co-Evolving Inspectable Graders with Self-Improving Agents (2026)") §5.3), and an always-pass grader trained skills as well (§5.2); a post-hoc placebo scrambling which input caught which bug nearly reproduced an apparent feedback effect ([Auditing and Decomposing Feedback-Driven…](#/papers/liang2026testgen "Auditing and Decomposing Feedback-Driven Evolution in LLM Test Generation under the Oracle Problem (2026)") §4.6). A transfer claim needs an arm learned without the verdicts (ours).
- **The scorer may be what changed:** on released 7B SimpleRL pairs, most of the out-of-domain multiple-choice gain that copied answer extractors report is format gain, gone when one extractor reads both models alike; not so on a 32B pair ([Same Answer, New Box](#/papers/lyu2026sameanswer "Same Answer, New Box: How Much of RLVR's Out-of-Domain Gain Is Answer Format? (2026)") §4.1, §6).
- **Held-out targets leak into selection:** SynTra picked its hyperparameters by the hallucination rate on an MS MARCO validation set, one of its transfer tasks ([SynTra (Synthetic Transfer)](#/papers/jones2023syntra "Teaching Language Models to Hallucinate Less with Synthetic Tasks (2023)") App. B.1); Pandey et al.'s printed final prompt holds items from the MiniF2F test split.
- **What is learned can be too specific, or harmful elsewhere:** the GEPA agent that transferred below baseline carried sample-specific prompt changes ([Do Agent Optimizers Compound?](#/papers/wang2026compound "Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0 (2026)") §6.1–6.2), and the authors' own RELAI-VCL harness, called free of task-specific fixes, carries DOOM-task literals in its released Phase 1 gate; raw memory traces often hurt while general lessons carry ([Memory Transfer Learning (MTL](#/papers/kim2026memorytransfer "Memory Transfer Learning: How Memories are Transferred Across Domains in Coding Agents (2026)"); Memory across problems); harder math data helped in-domain and hurt easier tasks in other domains ([Revisiting Reinforcement Learning for…](#/papers/cheng2025guru "Revisiting Reinforcement Learning for LLM Reasoning from A Cross-Domain Perspective (2025)") §3.3); which prompt edits go with gains depends on the task, as associations ([Why Prompt Optimization Works,…](#/papers/gong2026whypo "Why Prompt Optimization Works, and Why It Sometimes Doesn't: A Causal-Inspired Edit-Level Analysis (2026)"); Prompt evolution). A DSL rare in pretraining may, like Guru's Logic and Tabular, gain only in-domain (ours; [Learning a rarely seen DSL in prompts](#/challenges/unseen_dsl_in_prompts)).

## Verifiable signal
The transfer effect is target success with the learned artifact minus without, on target tasks the loop never saw, beside the in-domain gain; the arms and controls: near_carry_over, far_carry_over. Far targets have no certificate, and their scores are reported as evidence.
