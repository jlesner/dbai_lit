# Minimal counterexamples

> Find the smallest database on which two queries differ, so that a person or an LLM can read why they differ.

## Challenge
Given Q1, Q2 and a database on which they differ, find the smallest database on which they still differ. There are two versions: the smallest sub-instance of a given database D, as RATest defines the problem ([RATest](#/papers/miao2019ratest "Explaining Wrong Queries Using Small Examples (2019)") §2.1), and the smallest database of any content, built from scratch. Size means rows first, then the number and magnitude of the values (our framing). The result must still be a valid counterexample: both queries deterministic on it, with no error or timeout ([Equivalence of nondeterministic queries](#/challenges/nondeterministic_equivalence)), and the schema's constraints satisfied ([Equivalence under schema constraints](#/challenges/schema_constrained_equivalence)). The method is Query and counterexample reduction; this page is the problem and its objective.

## What's known
- **Exact and heuristic reducers.** RATest solves the sub-instance version exactly by handing the provenance of one differing output tuple to a solver, so each solve is optimal for that tuple only ([RATest](#/papers/miao2019ratest "Explaining Wrong Queries Using Small Examples (2019)") §2.2). Cutting a counterexample to the provenance rows of one distinguishing output tuple keeps it a counterexample ([Speeding up symbolic reasoning…](#/papers/wang2018symbolic "Speeding up symbolic reasoning for relational queries (2018)") Lemma 5.5, PDF p. 15; a proof sketch). The SlabCity authors set RATest aside as "quite expensive" and able to "only support a limited SQL language" ([SlabCity](#/papers/dong2023slabcity "SlabCity: Whole-Query Optimization Using Program Synthesis (2023)") §6, PDF p. 12), and the SISelection authors call their own extractor a heuristic ([data-aware NL2SQL candidate selection](#/papers/kikot2026separating "Data-aware candidate selection in NL2SQL translation via small separating instances (2026)"); Query and counterexample reduction).
- **Today's refuters barely minimize.** VeriEQL's release fills every table with exactly the bound's number of rows, so its counterexamples are as large as the bound at which it found them (our reading). SpotIt raises the bound one at a time and calls its databases "guaranteed to be minimal" ([SpotIt](#/papers/klopfenstein2025spotit "SpotIt: Evaluating Text-to-SQL Evaluation with Formal Verification (2026)") §4.2, Alg. 1; §5, PDF p. 8): minimal in the per-table bound only (our reading).

Still open (ours): a reducer that finds counterexamples smaller than greedy deletion reaches, including ones built from scratch below any sub-instance of D, on SQL beyond the fragments RATest supports, with each result re-validated by execution (§ Why it's hard, § Verifiable signal).

## Why it matters
- **LLM readers need small instances.** SQLDriller's LLM answers the English question on each counterexample. Its accuracy falls as tables grow, and the authors credit "the inherent tiny size of counterexamples" for keeping the method usable ([SQLDriller](#/papers/yang2025sqldriller "Automated Validating and Fixing of Text-to-SQL Translation with Execution Consistency (2025)") §7, PDF p. 22). The SISelection authors call the extraction of "a minimal separating instance" "a logical problem of utmost practical importance" ([data-aware NL2SQL candidate selection](#/papers/kikot2026separating "Data-aware candidate selection in NL2SQL translation via small separating instances (2026)") §5), and DPC asks its Tester agent for "a sufficient but minimal set of data" ([DPC (Dual-Paradigm Consistency)](#/papers/li2026dpc "DPC: Training-Free Text-to-SQL Candidate Selection via Dual-Paradigm Consistency (2026)") App. A.2). Every LLM referee in [Checking text-to-SQL against intent](#/challenges/text_to_sql_verification) § Why it's hard and § What's known reads such an instance.
- **People need them too.** RATest offers the smallest counterexample as "an explanation of why" two queries "are not equivalent" ([RATest](#/papers/miao2019ratest "Explaining Wrong Queries Using Small Examples (2019)") abstract), and was deployed in a database course (§8). EvoSQL's authors drop unneeded rows after the search because "readability of the generated data is important" ([EvoSQL](#/papers/castelein2018evosql "Search-Based Test Data Generation for SQL Queries (2018)") §3.3.1, PDF p. 5).
- **The loop and the benchmarks.** In the [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop) a counterexample goes back to the describer as feedback text, and in [Benchmarks with checkable ground truth](#/challenges/checkable_benchmark_ground_truth) it is the label a reviewer re-runs. A few rows fit in a prompt and in a review; a benchmark database doesn't (our reasoning).

**Size of the gain:** enabler, our estimate. The quantity it lifts is the readers' accuracy in the three challenges above (LLM referees, the loop's describer, benchmark reviewers), measured here as the rows in the validated counterexamples handed to them, against a no-LLM reducer on the same pairs. The reason: the gain shows up wherever a reader's accuracy depends on the instance's size (§ Why it matters).

## Why it's hard
- **NP-hard in general.** Finding the smallest counterexample sub-instance is NP-hard ([RATest](#/papers/miao2019ratest "Explaining Wrong Queries Using Small Examples (2019)") abstract), in data complexity already for queries with projection, join and difference (Tab. 1, Thm 8).
- **Deletion has limits.** Greedy reduction stops at a local minimum (Query and counterexample reduction). Size must count copies (our reasoning): some multiplicity-sensitive pairs agree on every database without repeated atoms, yet are not equivalent ([Equivalence of Queries That…](#/papers/cohen2009multiplicities "Equivalence of Queries That Are Sensitive to Multiplicities (2009)") Remark 4.8, PDF p. 13). A smaller database built from scratch can exist when every sub-instance of D is larger, and deletion can't reach it (our reasoning).
- **Theory sizes only simple fragments.** Where a complete test family exists ([Query equivalence: prove or refute](#/challenges/query_equivalence) § What's known), a separating database is built from the queries, at about their size (our reading of those constructions); for tableaux under [set semantics](#/glossary/set-semantics), the containee's rows under a one-to-one valuation separate them whenever containment fails ([Equivalences Among Relational Expressions…](#/papers/sagiv1980union "Equivalences Among Relational Expressions with the Union and Difference Operators (1980)") §4, PDF p. 9). Such bounds can be loose ([Few Rows Tell Them Apart](#/papers/cohen2026fewrows "Few Rows Tell Them Apart: Equivalence of Queries Mixing Set and Bag Semantics (2026)") §7), and for sum-queries the published construction uses very large values ([Deciding Equivalences among Conjunctive…](#/papers/cohen2007aggregate "Deciding Equivalences among Conjunctive Aggregate Queries (2007)") proof of Thm 9.5, PDF p. 40). Outside those fragments nothing bounds the size.
- **Shrinking can break validity.** Dropping rows keeps keys but can break foreign keys, which RATest has to handle separately ([RATest](#/papers/miao2019ratest "Explaining Wrong Queries Using Small Examples (2019)") §2.1, §4.3). It can also leave an instance that separates the queries only through a tie. A tie-free counterexample can need more rows than the tied one a bounded search finds first (our reading of [SpotIt+](#/papers/tremante2026spotitplus "SpotIt+: Verification-based Text-to-SQL Evaluation with Database Constraints (2026)") Example D.3). A reducer's output is a [certificate](#/glossary/certificate) only after re-execution: RATest's printed aggregate constraint can return a sub-instance on which the queries agree.

## Verifiable signal
Cheap and sound for validity and size: load the candidate into a real engine with the schema's constraints declared, pass the determinism pre-check, and run both queries. They must differ, and the size is a count. 1-minimality (no single row can be dropped) costs one re-execution per row. Global minimality can be checked only where an exact method or a theorem's bound applies (RATest on its fragments). So the reward is the size of a validated counterexample, compared with a baseline reducer's on the same pair (our reasoning).
