# Bringing compact models to frontier accuracy

> Make a small, cheap model as reliable as a frontier model on checkable SQL tasks, without retraining it (or with only a little training).

<p class="tags"><a class="tag" href="#/tags/compact">compact</a><a class="tag" href="#/tags/promptopt">promptopt</a><a class="tag" href="#/tags/scaling">scaling</a></p>

## Challenge
Close the gap on SQL synthesis and counterexample discovery, and find *which* inference-time lever pays off, and when: each lever's gain depends on the model and the task (§ Why it's hard).

## What's known
- **A frontier model can optimize once, offline, for a compact model** that only runs the result. SkillOpt reports larger gains with a frontier optimizer than with a target-matched one in every cell it tests ([SkillOpt](#/papers/yang2026skillopt "SkillOpt: Executive Strategy for Self-Evolving Agent Skills (2026)") §4.3); GPT-5's instructions, one per question cluster, raised small students' mean on three tasks, the smallest most on MedQA ([Instruction Retrieval at Inference…](#/papers/alkiek2025instructionretrieval "Instruction Retrieval at Inference Time for Small Language Models (2025)") §5); with a skill GPT-5.4 revised against the benchmark's checker, Qwen3.5-4B beat Qwen3.5-9B with human-written or any baseline's skills on SWE-Skills-Bench ([SKILLER](#/papers/dang2026skiller "SKILLER: Language-Level Reinforcement Learning for Reusable Skill Extraction in Small Language Models (2026)") § "Natural-Language Skill Optimization", § "Main Results and Analysis"), though SKILLER doesn't lead every baseline on every benchmark (Tab. 1).
- **What it writes must fit the executor** (ours). Larger models' memory gave smaller ones mixed results ([Dynamic Cheatsheet](#/papers/suzgun2025cheatsheet "Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory (2025)") §5); frontier-written skills lifted smaller executors less than a 27B model's, frontier procedures assuming "a coding robustness that smaller executors lack", the authors say ([Self-Evolving Code-with-Image Reasoning](#/papers/yang2026codewithimage "Self-Evolving Code-with-Image Reasoning (2026)") §5.4); a stronger teacher's rules helped a 4B student more when each had to make the student's rerun pass ([SKILL-KD](#/papers/shi2026skillkd "SKILL-KD: Contrastive Skill Distillation for LLM Agents (2026)") §3.2, §5.2, Tab. 3).
- **Whether a compact model can optimize for itself is open** (Hyper-reflection); older evidence leans against it (ours; counter-cases there): as their own optimizer and scorer, Mistral 7B and Llama-2 13B and 70B found instructions scoring below plain chain-of-thought ([Revisiting OPRO](#/papers/zhang2024opro "Revisiting OPRO: The Limitations of Small-Scale LLMs as Optimizers (2024)") §3.2), and smaller models gained less, or inconsistently, from memory they curated ([Dynamic Cheatsheet](#/papers/suzgun2025cheatsheet "Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory (2025)") §4.5). A counter-case, where the environment decides what is stored: on ALFWorld, gpt-4o-mini with its own successful trajectories about matched the fixed-database agent on gpt-4o, "similar" in the authors' word ([Self-Generated In-Context Examples Improve…](#/papers/sarukkai2025selfgenerated "Self-Generated In-Context Examples Improve LLM Agents for Sequential Decision-Making Tasks (2025)") §5.1, Tab. 2 caption).
- **Structure and step checks can stand in for scale** (ours): an 8B model running pre-written control combinators on long inputs about matched the mean of a 70B model writing its own control code ([λ-RLM ("The Y-Combinator for LLMs")](#/papers/roy2026ycombinator "The Y-Combinator for LLMs: Solving Long-Context Rot with $\lambda$-Calculus (2026)") §5.1 C2); per-step symbolic checks with repair lifted 3–4B models far more than frontier ones on long relation chains ([Reason Popper-ly](#/papers/chen2026popper "Reason Popper-ly: Patching In-Context Reasoning with Inductive Logic Programming (2026)") §4, Tab. 1); with code execution, small thinking models held up on a composition-depth benchmark where small Instruct ones still declined ([Tool Use Reduces Depth-Induced…](#/papers/koplow2026depthcollapse "Tool Use Reduces Depth-Induced Collapse in OOD Reasoning (2026)") Fig. 4: [Whole-job reliability of multi-step LLM work](#/challenges/whole_job_reliability) § What's known).
- **Fixing the harness can lift a compact model with no training** (ours). Driving an SQL client's database agent with local open models, Bozoglan et al. found most failed runs had called tools, models that "act, establish something true, and then lose it at the boundary between the model and the server"; server-side changes touching no model or prompt raised several models' passes, "field observations with known confounds, not an ablation" ([What Stops a Small…](#/papers/bozoglan2026slmdbagent "What Stops a Small Language Model From Driving a Database Agent (2026)") abstract, §1, §7).
- **Post-hoc operators didn't help frozen small code models:** on the models and benchmarks tested, no semantic operator (selection, verification, repair and others) beat best-of-N on hidden tests at matched compute; the only accuracy gain came from a better code extractor, larger for the weaker model ([Selection Without Signal, Recovery…](#/papers/iscan2026falsification "Selection Without Signal, Recovery Through Expression: A Measurement Study of Post-Hoc Falsification Operators for Frozen Small Code Models (2026)") abstract; refute-first's gain not significant, Tab. 8).

## Why it matters
- **Queries and data can stay in house.** LASER's authors argue that sending production SQL, schemas and sometimes execution feedback to an LLM API "raises serious privacy and compliance concerns" ([LASER](#/papers/li2026laser "LASER: A Data-Centric Method for Low-Cost and Efficient SQL Rewriting based on SQL-GRPO (2026)") §1). Their locally run 8B and 14B rewriters need far less GPU memory than the DeepSeek-R1 baselines and cost less than all six baselines on DSB (§6.3, Tab. 4, where GPT-4o rewrites faster). They are trained, and show the hardware side, not parity: their one-database equivalence rate trails a frontier baseline on two of five benchmarks (Tab. 3, Tab. 5).
- **A checker turns cheap samples into answers.** With repeated sampling, Llama-3-8B exceeded GPT-4o's single-sample score on competitive programming and Lean proofs, and a cheaper open model with several attempts solved more SWE-bench Lite issues than one attempt of GPT-4o or Claude 3.5 Sonnet, at a fraction of the cost, the Monkeys authors report ([Large Language Monkeys](#/papers/brown2024monkeys "Large Language Monkeys: Scaling Inference Compute with Repeated Sampling (2024)") §1, §2.3, Tab. 1; the extra samples spend part of the saving, ours). These are coverage scores: solved if any sample passes, for code by tests hidden from the model (§2). Where tests pass wrong code, resampling can't lift a weaker model to a sufficiently strong model's single-sample accuracy, Stroebl et al. argue ([The Limits of Inference…](#/papers/stroebl2024resampling "The Limits of Inference Scaling Through Resampling (2024)") abstract, §3; HumanEval, MBPP; [Best-of-n sampling](#/glossary/best-of-n-sampling) with a verifier).
- **The methods carry over.** Prompt optimization, checked sampling and budget control are the research's general methods; a cheap reliable proposer cheapens every run of [Benchmarks with checkable ground truth](#/challenges/checkable_benchmark_ground_truth), [Refuting faulty rewrite rules](#/challenges/faulty_rewrite_rules) and the [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop) (ours).

**Size of the gain:** step change, our estimate. It is measured as the hardware a deployment needs to reach a given accuracy on a checkable SQL task. The reason: one local server instead of an API or a large cluster changes where the work can run, not just its price.

## Why it's hard
- **A frontier-written rule can derail a small model:** in one worked SEPO trace, a 397B architect's self-verification rule sent its 8B worker into an "infinite repetition loop", and the next edit removed it ([SEPO](#/papers/ma2026sepo "SEPO: Evidence-Grounded Prompt Optimization via Structural Editing (2026)") App. E.2).
- **Prompt optimization needs headroom on both sides.** A model that almost never succeeds gives the search nothing to select on ("the fitness landscape is flat", [Optimize Cheap](#/papers/oved2026crosstier "Optimize Cheap, Deploy Strong: Cost-Aware Cross-Tier Transfer for Evolutionary Optimization (2026)") §9; ContraPrompt needs "at least one successful retry per training example", [ContraPrompt](#/papers/rishav2026contraprompt "ContraPrompt: Contrastive Prompt Optimization via Dyadic Reasoning Trace Analysis (2026)") §9; DSPy's bootstrapping, a few passing training examples, [DSPy](#/papers/khattab2023dspy "DSPy: Compiling Declarative Language Model Calls into Self-Improving Pipelines (2024)") §4); a seed near the model's prompting ceiling leaves nothing to gain ([RLMOpt](#/papers/satheesha2026rlmopt "RLMOpt: Adaptive Prompt Optimization via Recursive Language Models (2026)") abstract, §6.2; SAMMO left GPT-4 out for "negligible headroom", [SAMMO](#/papers/schnabel2024sammo "Symbolic Prompt Program Search: A Structure-Aware Approach to Efficient Compile-Time Prompt Optimization (2024)") §5.1). For SQL counterexamples the floor is the risk: an 8B model that rarely finds one gives the checker nothing to reward (ours).
- **Which lever pays off depends on the task and the question's difficulty** ([Large Language Monkeys](#/papers/brown2024monkeys "Large Language Monkeys: Scaling Inference Compute with Repeated Sampling (2024)") §2.3, Fig. 4). With every call charged, across mathematics, programming and agent tasks, Yang et al. report Claude Opus 5.5 answering once as the most accurate tested configuration outside programming, against low-cost reasoning models given extra inference ([How Much Can Language…](#/papers/yang2026selfpot "How Much Can Language Models Gain from Test-Time Computation? (2026)") §1, §3.4).
- **And on the model.** SAMMO's candidates score with "only weak correlation" across LLMs, so prompts "may need to be optimized separately for each LLM" ([SAMMO](#/papers/schnabel2024sammo "Symbolic Prompt Program Search: A Structure-Aware Approach to Efficient Compile-Time Prompt Optimization (2024)") §5.2); one task "moves from highly optimizable to flat by changing the executor model alone" ([Prompt Optimization Is a Coin Flip](#/papers/zhang2026coinflip "Prompt Optimization Is a Coin Flip: Diagnosing When It Helps in Compound AI Systems (2026)") §5); "Stronger models do not necessarily improve more" ([Benchmarking Prompt Optimization of…](#/papers/lesort2026chess "Benchmarking Prompt Optimization of Large Language Models With Chess (2026)") §6). Even model order can flip: with a code interpreter, GPT-4o-mini and GPT-3.5 beat GPT-4o on two tasks, the authors say because GPT-4o chose text over code ([Steering Large Language Models…](#/papers/chen2024steering "Steering Large Language Models between Code Execution and Textual Reasoning (2025)") §2.2, Figs. 3–4), though over all fourteen GPT-4o leads (Tab. 2); every model but GPT-4-Turbo extracted web data more accurately reading each page than through its own scraper ([AutoScraper](#/papers/huang2024autoscraper "AutoScraper: A Progressive Understanding Web Agent for Web Scraper Generation (2024)") §6.1, Tab. 4).
- **Handing the work to an engine can backfire.** Routed to logic solvers, 7–8B models scored below their own zero-shot prompting on a mixed set, mostly from invalid solver input ([Reliability that holds with size, by handing the procedure to an engine](#/challenges/engine_offloading_with_size) § Why it's hard); fine-tuning on GPT-4o's formalizations narrowed the gap to GPT-4o without closing it ([Adaptive LLM-Symbolic Reasoning via…](#/papers/xu2025adaptive "Adaptive LLM-Symbolic Reasoning via Dynamic Logical Solver Composition (2026)") §3.3, §3.7, Fig. 4, Tab. 2 vs Tab. 1). A local 4B Qwen model translating ordering puzzles once for a solver beat repeated-sampling votes with one call, but on typed constraints direct answering stayed ahead for it, and a second small model did worse there with the pipeline ([Resource-Aware Neuro-Symbolic Reasoning for…](#/papers/ramirez2026vfr "Resource-Aware Neuro-Symbolic Reasoning for Local Small Language Models (2026)") abstract, §7, Tab. 5).
- **[Self-correction](#/glossary/self-correction) fares worst at equal token cost** (ours). No method tested reliably beat majority voting on Qwen2.5 1.5B–7B in math, and Self-Refine and the authors' forced Reflexion stayed below it even at 7B ([Sample More, Reflect Less](#/papers/mirzaei2026samplemore "Sample More, Reflect Less: Self-Refine and Reflexion Lose to Repeated Sampling at Equal Token Cost, from 1.5B to 7B (2026)") abstract; [Whole-job reliability of multi-step LLM work](#/challenges/whole_job_reliability) § Why it matters); in code, self-repair often gained modestly once its cost was counted ([Is Self-Repair a Silver…](#/papers/olausson2023selfrepair "Is Self-Repair a Silver Bullet for Code Generation? (2024)") abstract; Best-of-n sampling with a verifier), more with a stronger model's feedback (§4.2; Agent loop with database and verifier tools).
- **Choosing the lever per question costs compute too.** Compute-optimal scaling needs a per-question difficulty estimate, which Snell et al. derive from many samples, call "extremely costly", and leave out of their accounting ([compute-optimal test-time scaling](#/papers/snell2024scaling "Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters (2024)") §3.2, App. C). In SQL, the checker's outcome on a first attempt (a quick counterexample, a timeout, *unknown*) might be a cheaper signal (ours).
- **Retraining has limits of its own.** Pure RL's gains depend on the base model and the task, and some small bases gained little or lost from it (the evidence: [RL with verifiable rewards](#/glossary/rl-with-verifiable-rewards-rlvr) (RLVR / [GRPO](#/glossary/grpo))); this challenge looks first for levers that need no retraining.
- **A matching score can hide damage.** 4-bit agents kept their benchmark score while tool-name errors rose significantly in two of the ten model–domain cells, one of them hidden by the benchmark's tolerance of failed calls ([Flat Score, Amplified Failures](#/papers/jang2026flatscore "Flat Score, Amplified Failures: How the Error Budget Masks Damage in Quantized LLM Agents (2026)"): [Whole-job reliability of multi-step LLM work](#/challenges/whole_job_reliability) § What's known). Parity needs per-step checks, not just the final score (ours).

## Verifiable signal
Execution certifies a counterexample once the pair is deterministic (Determinism pre-check), and so a non-equivalent pair, but one database is only evidence for an equivalent pair, which a prover would certify (ours). This makes compute-for-accuracy trade-offs measurable.

**Named attack (ours):** a frontier-written skill for SQL counterexample discovery, kept only where the 8B model's checked reruns pass (after [SKILLER](#/papers/dang2026skiller "SKILLER: Language-Level Reinforcement Learning for Reusable Skill Extraction in Small Language Models (2026)") and [SKILL-KD](#/papers/shi2026skillkd "SKILL-KD: Contrastive Skill Distillation for LLM Agents (2026)"), § What's known); measured as the hardware a target accuracy needs.
