# Bringing compact models to frontier accuracy

> Make a small, cheap model as reliable as a frontier model on checkable SQL tasks, without retraining it (or with only a little training).

<p class="tags"><a class="tag" href="#/tags/llm">llm</a><a class="tag" href="#/tags/promptopt">promptopt</a></p>

## Challenge
Close the gap on SQL synthesis and counterexample discovery, and work out *which* inference-time lever pays off, and when.

## Why it matters
- **Queries and data can stay in house.** The LASER authors argue that sending production SQL, schemas and sometimes execution feedback to an LLM API "raises serious privacy and compliance concerns" ([LASER](#/papers/li2026laser "LASER: A Data-Centric Method for Low-Cost and Efficient SQL Rewriting based on SQL-GRPO (2026)") §1). Their 8B and 14B rewriters run locally, on far less GPU memory than the DeepSeek-R1 baselines and at a lower cost than all six baselines in their cost table (§6.3, Tab. 4), though GPT-4o rewrites faster. LASER gets there by training.
- **A checker turns cheap samples into answers.** The Monkeys authors report that with repeated sampling, Llama-3-8B exceeds GPT-4o's single-sample score on competitive programming and Lean proofs ([Large Language Monkeys](#/papers/brown2024monkeys "Large Language Monkeys: Scaling Inference Compute with Repeated Sampling (2024)") §1), and that a cheaper open model with several attempts solved more SWE-bench Lite issues than one attempt of GPT-4o or Claude 3.5 Sonnet, at a fraction of the cost (§2.3, Tab. 1). Those scores count a problem as solved when any sample passes tests the model never sees; where tests pass wrong code, Stroebl et al. argue resampling can't lift a weaker model to a sufficiently strong model's single-sample accuracy ([The Limits of Inference…](#/papers/stroebl2024resampling "The Limits of Inference Scaling Through Resampling (2024)") abstract, §3; HumanEval, MBPP; [Best-of-n sampling](#/glossary/best-of-n-sampling) with a verifier).
- A frontier model can optimize once, offline, for a compact model that only runs the result: SkillOpt reports larger gains with a frontier optimizer than with one matched to the target in every cell it tests ([SkillOpt](#/papers/yang2026skillopt "SkillOpt: Executive Strategy for Self-Evolving Agent Skills (2026)") §4.3), though memory written by larger models gave smaller ones mixed results ([Dynamic Cheatsheet](#/papers/suzgun2025cheatsheet "Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory (2025)") §5). Whether a compact model can optimize for itself is open (Hyper-reflection); older evidence leans against it (our reading; counter-cases there): as their own optimizer and scorer, Mistral 7B and Llama-2 13B and 70B found instructions that scored below plain chain-of-thought prompts ([Revisiting OPRO](#/papers/zhang2024opro "Revisiting OPRO: The Limitations of Small-Scale LLMs as Optimizers (2024)") §3.2), and smaller models gained less, or inconsistently, from memory they curated themselves ([Dynamic Cheatsheet](#/papers/suzgun2025cheatsheet "Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory (2025)") §4.5). A cheap reliable proposer lowers the cost of every run of [Benchmarks with checkable ground truth](#/challenges/checkable_benchmark_ground_truth), [Refuting faulty rewrite rules](#/challenges/faulty_rewrite_rules) and the [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop) (our reasoning).

**Size of the gain:** step change, measured as the hardware a deployment needs to reach a given accuracy on a checkable SQL task. One local server instead of an API or a large cluster ([LASER](#/papers/li2026laser "LASER: A Data-Centric Method for Low-Cost and Efficient SQL Rewriting based on SQL-GRPO (2026)") Tab. 4) changes where the work can run, not just its price. LASER shows the hardware side, not parity: its one-database equivalence rate trails a frontier baseline on two of its five benchmarks ([LASER](#/papers/li2026laser "LASER: A Data-Centric Method for Low-Cost and Efficient SQL Rewriting based on SQL-GRPO (2026)") Tab. 3, Tab. 5). Extra samples spend part of the saving ([Large Language Monkeys](#/papers/brown2024monkeys "Large Language Monkeys: Scaling Inference Compute with Repeated Sampling (2024)") Tab. 1), and on questions beyond the small model's capabilities a larger model wins ([compute-optimal test-time scaling](#/papers/snell2024scaling "Scaling LLM Test-Time Compute Optimally can be More Effective than Scaling Model Parameters (2024)") §7). This is our estimate.

## Verifiable signal
The tasks themselves supply it: counterexamples are checked by execution, and generated examples by execution or a prover. That is what makes compute-for-accuracy trade-offs measurable.
