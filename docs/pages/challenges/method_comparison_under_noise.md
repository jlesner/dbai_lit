# Comparing LLM methods under noise

> Reported gains among prompts, optimizers, verifiers and training recipes often sit inside run-to-run and small-sample noise, or are scored on the set that picked the winner. Certified, renewable SQL test items make the comparison cheap to redo.

## Challenge
Work on LLM methods for checkable problems asks which methods make models reliable, and every answer is a comparison. Comparisons on this site fail in five recurring ways, most often in prompt optimization:
- **Gains inside the noise.** A skill-optimization study finds its GEPA gain "cannot be separated from the agent's run-to-run variance" ([Skill Issue](#/papers/kozyrev2026skillissue "Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents (2026)") abstract); RLMOpt's authors treat differences within the per-run standard error as ties and call their margins over GEPA "generally comparable" to it ([RLMOpt](#/papers/satheesha2026rlmopt "RLMOpt: Adaptive Prompt Optimization via Recursive Language Models (2026)") §4, §7); Coin Flip's authors find that question difficulty explains far more variance "than any prompt effect" ([Prompt Optimization Is a Coin Flip](#/papers/zhang2026coinflip "Prompt Optimization Is a Coin Flip: Diagnosing When It Helps in Compound AI Systems (2026)") §3.2). Greedy decoding is no floor: s1's scores "change significantly across runs" with the same seeds and greedy sampling ([s1](#/papers/muennighoff2025simple "s1: Simple test-time scaling (2025)") App. B), and batched serving keeps greedy decoding "only approximately reproducible" ([Measuring Crystallization in Text-to-SQL](#/papers/wang2026crystallization "From Test-Time Scaling to Reusable Memory: Measuring Crystallization in Text-to-SQL (2026)") §4).
- **The selection set is the reported set.** Picking among about ten candidates on a small validation set "is a multiple-testing problem" ([ESPO](#/papers/liu2026espo "ESPO: Error-Structured Prompt Optimization via Diagnose, Diversify, and Stabilize (2026)") §3.4), and the winner is often reported on that same set: LSE reports the best holdout score reached over 25 rounds ([Learning to Self-Evolve (LSE)](#/papers/chen2026lse "Learning to Self-Evolve (2026)") App. A); Adaptive-GEPA's "final selection reuses the same validation set" ([Adaptive-GEPA](#/papers/chen2026adaptivegepa "Adaptive-GEPA: Make Your Harness Fit Heterogeneous Requests (2026)") App. L); FLARE's Table 1 takes each method's best configuration across a sweep whose cells are the reported scores, though its §3 says the test set "never informs prompt selection" ([FLARE](#/papers/sundararaman2026flare "FLARE: Few-shot Learning-based Adaptive Reflective Engine (2026)") Tab. 1–2, §3; our reading of the tables); ADAS's released runs report each archive's best test-scoring agent. Early optimizers did it too: ProTeGi reports test F1 "based on maxpooling over the final beam of candidates" ([ProTeGi](#/papers/pryzant2023protegi "Automatic Prompt Optimization with 'Gradient Descent' and Beam Search (2023)") §3.2; our reading), and EvoPrompt's BBH development set is "a subset from the test set" ([EvoPrompt](#/papers/guo2023evoprompt "EvoPrompt: Connecting LLMs with Evolutionary Algorithms Yields Powerful Prompt Optimizers (2024)") §4.4). RL papers do it with checkpoints: Uesato et al. "select the best model of the 5, based on final-answer test error" ([process- vs outcome-based feedback](#/papers/uesato2022process "Solving math word problems with process- and outcome-based feedback (2022)") §2.6). An optimizer shown the selection items can memorize them (Prompt evolution and Critique-and-edit prompt refinement).
- **Unequal comparisons.** Rivals run each other's baselines in their own setups: ReSequel attributes gaps to earlier numbers to "the underlying LLMs … indicating strong sensitivity" ([ReSequel](#/papers/fathollahzadeh2026resequel "ReSequel: Robust LLM-assisted Query Rewriting and Optimization using Templatization and Sampling (2026)") §7.2), and LASER represents E3-Rewrite by a naive-GRPO model it trained itself ([LASER](#/papers/li2026laser "LASER: A Data-Centric Method for Low-Cost and Efficient SQL Rewriting based on SQL-GRPO (2026)") §6.1.3). Extra tokens raise accuracy by themselves, Mirzaei et al. argue, so they score each method against repeated sampling at its own measured token cost ([Sample More, Reflect Less](#/papers/mirzaei2026samplemore "Sample More, Reflect Less: Self-Refine and Reflexion Lose to Repeated Sampling at Equal Token Cost, from 1.5B to 7B (2026)") abstract).
- **The metric measures something else.** NPO's authors found that "formatting errors accounted for a nontrivial fraction of observed failures and could therefore distort the comparison between optimization methods" ([Naive Prompt Optimization (NPO)](#/papers/chang2026npo "Naive Prompt Optimization: Rethinking the Need for Complex Prompt Search (2026)") §2.4). On BIRD, scoring by counterexample search instead of one test database lowers every method's accuracy and reorders the ranking ([SpotIt](#/papers/klopfenstein2025spotit "SpotIt: Evaluating Text-to-SQL Evaluation with Formal Verification (2026)") §5, Tab. 3). A gain under a reward need not come from the reward ([Weak checkers get exploited](#/challenges/weak_checker_exploitation)).
- **Baselines that don't reproduce.** Two later groups re-ran TextGrad below its reported prompt-optimization numbers (Critique-and-edit prompt refinement).

## Why it matters
- **Selection turns noise into false gains.** An optimizer keeps the candidate that scored highest, so on small sets it keeps lucky ones ([ESPO](#/papers/liu2026espo "ESPO: Error-Structured Prompt Optimization via Diagnose, Diversify, and Stabilize (2026)") §3.4). Reusing one set over many rounds compounds this, as later candidates adapt to it: REUSE's authors report false promotions by current self-improvement systems' rules, judged on a held-out estimate ([Which Self-Improvements Should We…](#/papers/sun2026reuse "Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks (2026)") abstract, §3.1; one tabular task). This is the noise analogue of [Weak checkers get exploited](#/challenges/weak_checker_exploitation) (our reading).
- **SQL can supply what the papers lack.** The Skill Issue authors name the bottleneck: settling their question "would take more tasks than one repository's history yields" ([Skill Issue](#/papers/kozyrev2026skillissue "Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents (2026)") abstract). Certified SQL items are cheap to make and score without a judge; the argument's home is [Benchmarks with checkable ground truth](#/challenges/checkable_benchmark_ground_truth) § Why it matters.

**Size of the gain:** enabler, measured as the share of reported method gains on checkable problems that survive re-scoring on fresh certified items under a paired test fixed in advance. It shows up in [Bringing compact models to frontier accuracy](#/challenges/compact_model_accuracy) and the [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop), whose claims are all comparisons. This is our estimate.

## Verifiable signal
Re-score the chosen method on fresh items never used in selection, with a paired test fixed in advance, against an A/A floor (the same method scored twice). The papers already use each part: an A/A comparison and a [sign test](#/glossary/sign-test) over the tasks where two runs disagree ([Skill Issue](#/papers/kozyrev2026skillissue "Skill Issue: Lessons from Optimizing Repository SKILLs for Coding Agents (2026)") §4.2), [McNemar's exact test](#/glossary/mcnemars-exact-test) on paired items, read as "bounded, directional evidence" ([SQL-Zero](#/papers/pedrozo2026sqlzero "SQL-Zero: Self-Evolving Text-to-SQL (2026)") §5), a paired bootstrap ([LLMs as a Jury](#/papers/liu2026jury "LLMs as a Jury: Cross-Model Consensus Can Outperform Process Reward Models for LLM Reasoning (2026)") App. A) or a two-stage one over databases, then questions, keeping each question's seed results together ([Measuring Crystallization in Text-to-SQL](#/papers/wang2026crystallization "From Test-Time Scaling to Reusable Memory: Measuring Crystallization in Text-to-SQL (2026)") §4), matched instances across methods ([Naive Prompt Optimization (NPO)](#/papers/chang2026npo "Naive Prompt Optimization: Rethinking the Need for Complex Prompt Search (2026)") §2.4), and acceptance rules that are tests inside the search (Prompt evolution, ESPO's bootstrap). A claim of no loss needs a margin fixed in advance: [When the Reward Suite Is Leaky](#/papers/zhang2026leaky "When the Reward Suite Is Leaky: A Preregistered Causal Contrast of Natural Verifier False Positives in RLVR (2026)") runs a non-inferiority test with the seed as the unit of inference and prices its own analysis freedom with family-adjusted p-values (§3.6, §4.1, §4.4). Where items can't be renewed, REUSE certifies promotions on a reused set by returning only decisions to the search and budgeting error over all promotion histories; its power falls as the run grows ([Which Self-Improvements Should We…](#/papers/sun2026reuse "Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks (2026)") abstract, §2.1–2.2; its live runs' procedure is undescribed). In SQL the fresh items can be certified pairs: an LLM proposer makes them on demand, a counterexample is checked by running two queries after a Determinism pre-check, and no judge adds noise. The check is cheap, and sound up to the test's stated error rate (our reasoning); realistic hard pairs are [Sourcing realistic, hard query pairs](#/challenges/query_pair_sourcing)'s problem.
