# Canonical forms for queries

> Normal forms for useful SQL fragments, so that comparing two queries' forms decides (or nearly decides) equivalence. Sound when the forms match; outside fragments where a form is complete, silent when they don't.

<p class="tags"><a class="tag" href="#/tags/prove">prove</a><a class="tag" href="#/tags/rules">rules</a><a class="tag" href="#/tags/theory">theory</a></p>

## Challenge
Find [normal forms](#/glossary/normal-forms-1nf-2nf-3nf-bcnf), as canonical as possible, for useful SQL fragments, so that equivalence (or "close to equivalent") can be read off by comparing forms. Complete forms are known only for small fragments; beyond them, the provers' forms miss equivalences (ours).

## What's known
- **Canonical forms exist for fragments.** Under [set semantics](#/glossary/set-semantics), every [conjunctive query](#/glossary/conjunctive-query) has a minimal equivalent query, unique up to renaming of variables ([Optimal Implementation of Conjunctive…](#/papers/chandra1977conjunctive "Optimal Implementation of Conjunctive Queries in Relational Data Bases (1977)") Thm 12; later called the *core*). Aho, Sagiv and Ullman state the analogue for tableaux, without proof ([Equivalences among Relational Expressions](#/papers/aho1979equivalences "Equivalences among Relational Expressions (1979)") Thms. 4–5), and decide equivalence in polynomial time for "simple" tableaux, which they "feel" cover most practical select-project-join queries (Thm. 10, §1). Under [bag semantics](#/glossary/bag-semantics), conjunctive queries are equivalent exactly when they are isomorphic ([Optimization of real conjunctive queries](#/papers/chaudhuri1993real "Optimization of real conjunctive queries (1993)") Thm 5.2, stated without proof); over duplicate-free tables ([bag-set semantics](#/glossary/bag-set-semantics)), exactly when isomorphic after duplicate atoms are dropped (Thm 7.11; proved later, [Deciding Equivalences among Conjunctive…](#/papers/cohen2007aggregate "Deciding Equivalences among Conjunctive Aggregate Queries (2007)") §8). For positive queries without set variables, which combine bag and bag-set semantics, equivalence is isomorphism of reduced linear expansions over a [dense domain](#/glossary/dense-domain) ([Equivalence of Queries That…](#/papers/cohen2009multiplicities "Equivalence of Queries That Are Sensitive to Multiplicities (2009)") Thm. 4.7, §4); with set variables only subclasses are characterized (Tab. 1). So (ours) a canonical labelling of the query graph is a complete canonical form there, and self-joins are the hard part: without them ("linear" queries, which "occur frequently"), equivalence of aggregate queries is checked in polynomial time (for `cntd`, only without comparisons; [Deciding Equivalences among Conjunctive…](#/papers/cohen2007aggregate "Deciding Equivalences among Conjunctive Aggregate Queries (2007)") §5.2, Tab. I). Under set semantics, unions of conjunctive queries have unique minimal unions ([Equivalences Among Relational Expressions…](#/papers/sagiv1980union "Equivalences Among Relational Expressions with the Union and Difference Operators (1980)") §5), and the same paper gives a finite Church–Rosser system for unions of elementary differences, select-project-join-union-difference with no projection over a difference ([Equivalences Among Relational Expressions…](#/papers/sagiv1980union "Equivalences Among Relational Expressions with the Union and Difference Operators (1980)") §7, abstract).
- **Provers and tools already normalize.** UDP, SPES and QED normalize both queries before matching them ([UDP](#/papers/chu2018udp "Axiomatic foundations and algorithms for deciding semantic equivalences of SQL queries (2018)") §5.1–5.2, [SPES](#/papers/zhou2020spes "SPES: A Symbolic Approach to Proving Query Equivalence Under Bag Semantics (2022)") §4.2, [QED](#/papers/wang2024qed "QED: A Powerful Query Equivalence Decider for SQL (2024)") §4–5). QO-Verify compares the expression sets its optimizer generates after normalization ([QO-Verify](#/papers/narasayya2026qoverify "Leveraging Query Optimizers to Verify the Soundness of LLM-based Query Rewrites for Real-World Workloads, and More! (2026)") §2.2). EquiTrace makes aligning both queries to shared representatives an explicit proof objective, separate from rewrite search ([EquiTrace](#/papers/chen2026equitrace "Building SQL Equivalence Proofs from Query Rewrite Rules (2026)") §3.2, P2); in its authors' leave-one-out study the join-region-ordering canonicalizer, which puts a region of commutable joins into one order, is "the dominant individually load-bearing component", while many frequently used rules can each be dropped without losing a proof (§5.1). The XData grading authors use a canonical-form match as a sufficient test that a student query is correct ([Edit Based Grading of SQL Queries](#/papers/chandra2019grading "Edit Based Grading of SQL Queries (2019)") §1).

Still open (ours): canonical forms, built only from verified rules, for fragments beyond those above: with self-joins under aggregation, set variables, negation and NULLs.

## Why it matters
- **More proofs from the provers we have.** The QED authors trace misses by UDP and SPES to normal forms that fall back on syntactic matching, e.g. `[a+b=0]` against `[a=-b]` ([QED](#/papers/wang2024qed "QED: A Powerful Query Equivalence Decider for SQL (2024)") §1, §6.3), and WeTune's authors show an outer-join pair UDP's isomorphism test can't prove ([WeTune](#/papers/wang2022wetune "WeTune: Automatic Discovery and Verification of Query Rewrite Rules (2022)") §5.1, Fig. 5). SPES's authors trace most supported pairs it leaves unproved to missing normalization rules ([SPES](#/papers/zhou2020spes "SPES: A Symbolic Approach to Proving Query Equivalence Under Bag Semantics (2022)") §7.4), and EQUITAS's say some structurally different pairs with aggregates or [outer joins](#/glossary/outer-join) need structural transformation rules ([EQUITAS](#/papers/zhou2019equitas "Automated verification of query equivalence using satisfiability modulo theories (2019)") §6.4). The QO-Verify authors suggest normalizing scalar expression trees to raise their check's coverage ([QO-Verify](#/papers/narasayya2026qoverify "Leveraging Query Optimizers to Verify the Soundness of LLM-based Query Rewrites for Real-World Workloads, and More! (2026)") §2.2), and the EquiTrace authors read unproved LLM rewrites whose search saturated before the two sides met as "stronger evidence of a missing transformation or canonical representation" ([EquiTrace](#/papers/chen2026equitrace "Building SQL Equivalence Proofs from Query Rewrite Rules (2026)") §5.2). Stronger forms would turn *unknown* into proofs for [SQL features that verifiers don't cover](#/challenges/verifier_coverage_gaps) (ours).
- **Shared work across a workload.** The GEqO authors call detecting equivalent subexpressions "the first and crucial step" for view selection, view matching and multi-query optimization ([GEqO](#/papers/haynes2024geqo "GEqO: ML-Accelerated Semantic Equivalence Detection (2023)") §1). In their account, signatures (CloudViews' Merkle-tree hashes) find only syntactically identical subexpressions, and pairwise proving is quadratic (§1). In their synthetic test, signatures find far fewer equivalences (§7.5, Fig. 13a). In our reading, a canonical form is a hash key: one pass per query, with no pairwise calls. Workload reuse may gain more, but GEqO's evidence is synthetic (§7).
- **A cheap "equivalent" for grading and evaluation.** The XData authors match canonical forms because generating data for each student query is expensive ([Edit Based Grading of SQL Queries](#/papers/chandra2019grading "Edit Based Grading of SQL Queries (2019)") §4.7) and prior equivalence checkers don't handle many SQL features (§1). Spider's exact set match is a cruder form comparison (ours). The test-suite authors report that it rejects equivalent predictions ([Semantic Evaluation for Text-to-SQL…](#/papers/zhong2020testsuite "Semantic Evaluation for Text-to-SQL with Distilled Test Suites (2020)") §6.2, Tab. 1) and that its looser official version accepts some wrong ones (§5.3, §7).

**Size of the gain:** incremental, our estimate. It is measured as the share of equivalent query pairs that a form comparison certifies without a prover call or test data. The reason: full SQL has no computable canonical form, and fragment forms already sit inside the provers, so progress widens the fragment and cuts cost but doesn't make anything new possible.

## Why it's hard
- No *computable* canonical form exists for full SQL: it would decide equivalence, which is undecidable ([Query equivalence: prove or refute](#/challenges/query_equivalence)).
- Where canonical forms exist, computing and comparing them is costly: finding a conjunctive query's minimal equivalent is NP-hard ([Optimal Implementation of Conjunctive…](#/papers/chandra1977conjunctive "Optimal Implementation of Conjunctive Queries in Relational Data Bases (1977)") §5), and comparing two minimal queries is an isomorphism test as hard as [graph isomorphism](#/glossary/graph-isomorphism) (Thm 8).
- Rewrite systems may not terminate: UDP's key and foreign-key rewrites can loop like the [chase](#/glossary/chase) ([UDP](#/papers/chu2018udp "Axiomatic foundations and algorithms for deciding semantic equivalences of SQL queries (2018)") §5.1).
- Union (DNF) expansion can be exponential in the worst case ([Equivalences Among Relational Expressions…](#/papers/sagiv1980union "Equivalences Among Relational Expressions with the Union and Difference Operators (1980)"), proof of Thm 19), though UDP measured only small growth on its benchmarks ([UDP](#/papers/chu2018udp "Axiomatic foundations and algorithms for deciding semantic equivalences of SQL queries (2018)") §6.3).
- Distance between forms doesn't track semantic distance: a one-token change from `<` to `<=` is a real difference (ours).

## Verifiable signal
Matching normal forms are a proof, provided every rule used is verified. Different forms are no signal, unless the form is complete for the pair's fragment.
