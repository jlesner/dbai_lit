# Learning a rarely seen DSL in prompts

> Can a compact model learn a DSL that is rare in its training data, K through the open-source ngn/k engine, from the language's documentation and its engine alone, with what it learns kept in prompts?

<p class="tags"><a class="tag" href="#/tags/compact">compact</a><a class="tag" href="#/tags/general">general</a></p>

## Challenge
Mainstream DSLs (SQL, regular expressions, XPath) are common in training data, so a gain from a learning loop on them can't be told apart from a model recalling what it already half knew. A language the model has barely seen separates the two: if the loop of [Prompt-space self-play judged by an engine](#/challenges/prompt_space_self_play) lifts a compact model on K about as much as on XPath, it is teaching; if it lifts only XPath, it is reminding (ours). K has open-source engines (ngn/k is one) and many incompatible dialects, so the model must learn this one from its documentation and from what the engine accepts (ours).

## What's known
The listed work points two ways. In weights, [low-resource programming languages](#/glossary/low-resource-programming-language) (Julia, Lua, OCaml, R, Racket) have been taught by fine-tuning on code that a code LLM translated from Python, kept only when tests compiled from the source language passed: "a training corpus in the target low-resource language where all items have been validated with test cases" ([MultiPL-T](#/papers/cassano2023multiplt "Knowledge Transfer from High-Resource to Low-Resource Programming Languages for Code LLMs (2024)") abstract). In prompts, a method that hands the model a DSL's grammar "did not yield any improvements for DSLs that were likely to have been frequently encountered during pretraining (e.g., regular expressions, SQL)" ([Grammar Prompting](#/papers/wang2023grammar "Grammar Prompting for Domain-Specific Language Generation with Large Language Models (2023)") §5), which is why gains on mainstream DSLs say little about learning (ours). RL across six reasoning domains shows a like split in weights (our reading): math, code and science gained from training on other domains, while logic, simulation and table tasks gained mainly from their own data, which the authors hypothesize follows pretraining exposure ([Revisiting Reinforcement Learning for…](#/papers/cheng2025guru "Revisiting Reinforcement Learning for LLM Reasoning from A Cross-Domain Perspective (2025)") §3.1, Fig. 3).

Still open: a short search (2026-10-13) found no work that teaches a compact model a rare DSL through prompts alone with an engine, not a person, checking the examples it learns from (ours). Nearest: MEMCoder lifts 7–8B models on unseen libraries (not DSLs) with memory from benchmark test runs, documentation alone falling short ([Learning from Execution](#/papers/li2026privatelibrary "Learning from Execution: Self-Evolving Memory for Private-Library Code Generation (2026)") §III, §VI-A).

## Why it matters
- **It is the control of the research path**: without it, a gain on XPath or SQL could be recall.
- **It tests the general claim:** any language with an engine could become a tool for a compact model, without labelled data and without training (ours).
- **The language has users:** K's descendant q is the query language of kdb+, used for time-series data; whether skills learned on ngn/k carry over to q is open (ours).

**Size of the gain:** enabler. It is measured on the held-out success gain from the loop in [Reliability that holds with size, by handing the procedure to an engine](#/challenges/engine_offloading_with_size), which it shows to be learning or recall. Without it, no gain on a mainstream DSL can be credited to the loop. Our estimate.

## Why it's hard
- **A compact model may not get started:** with little K in training, early proposals and answers may rarely pass, leaving the loop few examples to learn from (ours; the same failure of small models writing poor memories, [Dynamic Cheatsheet](#/papers/suzgun2025cheatsheet "Dynamic Cheatsheet: Test-Time Learning with Adaptive Memory (2025)") §4.5). 7–8B models often wrote input for four logic solvers, "all 'under-resourced' formal languages", that didn't run ([Adaptive LLM-Symbolic Reasoning via…](#/papers/xu2025adaptive "Adaptive LLM-Symbolic Reasoning via Dynamic Logical Solver Composition (2026)") §3.3), and the authors of a constraint-DSL study call open models "unusable in practice" for OCL and Alloy ([A framework for assessing…](#/papers/delgado2026constraintdsl "A framework for assessing the capabilities of code generation of constraint domain-specific languages with large language models (2026)") §5.3.2). With the manual, examples and interpreter feedback, frontier models stayed far below their Python scores in esoteric languages ([EsoLang-Bench](#/papers/sharma2026esolang "EsoLang-Bench: Evaluating Genuine Reasoning in Large Language Models via Esoteric Programming Languages (2026)") abstract). In weights, STaR's authors report that bootstrapping needs few-shot success "above chance" ([STaR (Self-Taught Reasoner)](#/papers/zelikman2022star "STaR: Bootstrapping Reasoning With Reasoning (2022)") §6), and that rationalization, explaining a failed problem from its correct answer given as a hint, keeps the loop learning where failures alone give no signal (§3.2), though a model shown some hints in training learned that the answer always matched the hint (App. A.6). The gym's reference answers could be K's hint (ours).
- **A detour through a familiar language:** top agents often wrote Brainfuck and Befunge-98 via host-language generators; forbidding it, in a variant that also took away shell access, cut scores ([Frontier Coding Agents Use…](#/papers/sharma2026metaprogramming "Frontier Coding Agents Use Metaprogramming to Adapt to Unfamiliar Programming Languages (2026)") §3.2–3.3, App. A.12). A K gain could come that way (ours).
- **Dialects:** what the model knows of K may be another dialect's, which ngn/k rejects or reads differently (ours).
- **Some training data exists:** K is rare, not absent, so the control is graded familiarity, not none (ours).

## Verifiable signal
ngn/k runs every program; the task families and size settings are the same as for the mainstream DSL ([A gym of DSL tasks with answer keys made by code](#/challenges/dsl_gym)), so the two learning curves are compared directly: held-out success with and without the loop's skill document and example library, by model size.
