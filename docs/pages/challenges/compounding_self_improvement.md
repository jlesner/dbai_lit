# Self-improvement that compounds

> Self-improving LLM loops gain in the first round, then stall or regress. Make the gains compound: each round adds certified information, and each change is kept only if a certified, statistically controlled check shows it doesn't regress.

<p class="tags"><a class="tag" href="#/tags/harness">harness</a><a class="tag" href="#/tags/promptopt">promptopt</a><a class="tag" href="#/tags/rlvr">rlvr</a></p>

**Source:** added. It joins the compounding claim of [The self-improving SQL ↔ text ↔ verify loop](#/challenges/sql_text_round_trip_loop) to the measurement challenge of [Comparing LLM methods under noise](#/challenges/method_comparison_under_noise).

## Challenge
An improvement loop changes an LLM system round after round: its prompts, memory, skills or harness, and the listed loops mostly gain in the first round, then stall or fall (§ What's known). The challenge is to make compounding the rule in prompt space: every round adds certified information (counterexamples, harder items), and every change is kept only when a certified, statistically controlled test shows it doesn't regress.

## What's known
The listed loops that run several rounds mostly show one shape: most of the gain comes in the first round, then it stalls or falls.
- [Self-play](#/glossary/self-play) [text-to-SQL](#/glossary/text-to-sql) with no human pairs gains mostly in its first iteration, and "no sequence compounds" ([SQL-Zero](#/papers/pedrozo2026sqlzero "SQL-Zero: Self-Evolving Text-to-SQL (2026)") §5, Tab. 1).
- Self-training against a free, exact verifier gains for two rounds but never accelerates, and the starting model given more tries still beats the trained one ([Teacher-Free Self-Training Amplifies but…](#/papers/strozzi2026selftraining "Teacher-Free Self-Training Amplifies but Does Not Compound: A Pass@$K$ Crossover on a Free-Verifier Domain (2026)") abstract, §7).
- Self-improvement filtered by the model's own verification vanishes within two or three rounds as diversity falls ([Mind the Gap](#/papers/song2024mindgap "Mind the Gap: Examining the Self-Improvement Capabilities of Large Language Models (2025)") §5, Fig. 4).
- Self-play fine-tuning on text-to-SQL peaks after one iteration ([ExSPIN](#/papers/yan2025exspin "ExSPIN: Explicit Feedback-Based Self-Play Fine-Tuning for Text-to-SQL Parsing (2025)") Tabs. 6–7, §5.8).
- Puzzles a code model writes and solves, filtered by an interpreter, gave "a large benefit from the first iteration and small benefit from the second", read by its authors as a possible plateau ([Language Models Can Teach…](#/papers/haluptzok2022teach "Language Models Can Teach Themselves to Program Better (2022)") §4.3, Fig. 7; §5).

These five train weights. APE's iterative search shows "diminishing returns" as prompt quality "seems to stabilize after three rounds" ([APE](#/papers/zhou2022ape "Large Language Models Are Human-Level Prompt Engineers (2023)") §5.3); Promptbreeder keeps a diverse population; in one shown run training fitness "continues to increase throughout the run" ([Promptbreeder](#/papers/fernando2023promptbreeder "Promptbreeder: Self-Referential Self-Improvement Via Prompt Evolution (2023)") §1, §5, App. B), though runs stopped once it "appeared to plateau" (App. J.2). An agent accumulating its own successful trajectories as examples keeps improving with diminishing returns: "most gains occur within the first 25% of added training tasks" ([Self-Generated In-Context Examples Improve…](#/papers/sarukkai2025selfgenerated "Self-Generated In-Context Examples Improve LLM Agents for Sequential Decision-Making Tasks (2025)") §6.2, Fig. 2). In SkillLearnBench's multi-round runs (one category, one solver), self-revised skills' accuracy rose once and then fell sharply, while hints from a teacher that sees the human-written skill raised it every round: "external feedback gives the model something new to learn from" ([SkillLearnBench](#/papers/zhong2026skilllearnbench "SkillLearnBench: Benchmarking Continual Learning Methods for Agent Skill Generation on Real-World Tasks (2026)") §5.4, Fig. 4).

The loops that keep gaining share three things: a precise check on what is kept, a gate against regressions, and new information each round.
- In [self-distillation](#/glossary/self-distillation), held-out gain grows with the checker's precision, rejecting correct outputs costs little, and with a precise gate three rounds compound ([The Verifier is the Curriculum](#/papers/zhou2026curriculum "The Verifier is the Curriculum: Precision Sets the Return on Search in Code Self-Distillation (2026)") §8, Figs. 1 and 5; §6, Tab. 1; weights trained, one engine).
- Re-optimizing an agent on new tasks, an optimizer that rejects any change breaking an already-solved task averaged highest, while a GEPA-optimized prompt of lessons first fell below the unoptimized agent ([Do Agent Optimizers Compound?](#/papers/wang2026compound "Do Agent Optimizers Compound? A Continual-Learning Evaluation on Terminal-Bench 2.0 (2026)") §6.4, Tab. 7; the fall: [Gains made against a checker, carried beyond it](#/challenges/transfer_beyond_the_checker) § What's known).
- Harness edits kept only when an LLM ties a gain on some verification task to the edit (a task that failed every trial now passing one, or one that passed some trials now passing all) and ties no regression to it, and the edited harness then beats the current one's pass rate on a mostly fresh batch, never fell below the unedited harness in Tab. 1's twelve held-out results ([HarnessLens ("Verify Smarter](#/papers/xu2026harnesslens "Verify Smarter, Evolve Further: Efficient Harness Evolution through Behavior-Aware Verification (2026)") §5.2; the gate: App. A.4.1–A.4.2).
- A proof agent that rewrites its own prompts, tools and workflow against a fixed checker, practising on a set that retires solved problems for harder ones, gained more than on a fixed set ([Self-Modifying Lean Proof Agents](#/papers/li2026selfmodifying "Self-Modifying Lean Proof Agents with Verifier-Grounded Benchmark Coevolution (2026)") §4.1–4.2, Tab. 1; one run).
- In theorem proving, its authors say [expert iteration](#/glossary/expert-iteration) "plateaus" because correct proofs of the unproved statements are too rare to train on, while STP's self-generated conjectures, proved more often, give "more training signals, leading to better scaling" ([STP](#/papers/dong2025stp "STP: Self-play LLM Theorem Provers with Iterative Conjecturing and Proving (2025)") §4.4; weights trained).
- A data-bootstrapping loop for q stalled when the remaining problems were too hard and resumed after a pretraining phase on q code; its first run's gains were "largely illusory", from tests written with the solutions ([Technical Report](#/papers/hogan2025qlang "Technical Report: Full-Stack Fine-Tuning for the Q Programming Language (2025)") §3.1.1–3.1.2, Figs. 2, 4; weights trained).
- CwI switches from reading failures to re-running them once its probe score stalls, and its ablation puts part of the uplift on that step ([Self-Evolving Code-with-Image Reasoning](#/papers/yang2026codewithimage "Self-Evolving Code-with-Image Reasoning (2026)") §4.2, §5.5, on the validation split); its delivery gate is "not a guarantee against test regression" (§4.3).
- New verified examples that target each failure pattern raise the gains of three prompt optimizers ([FORGE](#/papers/yuan2026forge "Failure-Guided Co-Evolution of Prompts and Training Data (2026)") § "Transferability of Synthesized Data", Tab. 4; its verifier is an LLM); in our reading, new information of this kind is one way to avoid the stall.

## Why it matters
- **Compounding is the difference between a method and a system that keeps getting better.** A loop that gains once is one more method improvement; a loop whose per-round gain stays above zero keeps improving a system with no human labels and no weight training (our reasoning).
- **Every self-improvement loop needs the gate.** Reusing one evaluation set for keep-or-reject decisions promotes false improvements; a rule that returns only decisions to the proposer and budgets its error over all decision histories made none ([Which Self-Improvements Should We…](#/papers/sun2026reuse "Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks (2026)") abstract, Tab. 1; one tabular task). Scored against one reference program, an evolving test search looked like progress; audited against the other accepted programs, independent sampling at the same budget did better, and a post hoc placebo that scrambled which input caught which fault nearly reproduced the iterative loop's shifts ([Auditing and Decomposing Feedback-Driven…](#/papers/liang2026testgen "Auditing and Decomposing Feedback-Driven Evolution in LLM Test Generation under the Oracle Problem (2026)") §4.2–4.3, §4.6). Telling real improvement from gamed improvement inside a self-evolving loop is unsolved and costly: its authors call online detection "a new task", and only one of their protection settings returns more than it costs on clean runs ([HackProbe](#/papers/yang2026hackprobe "Harness-agnostic detection and immunization of reward hacking in self-evolving language models (2026)") §4, §4.3, Tab. 3). Noise is [Comparing LLM methods under noise](#/challenges/method_comparison_under_noise)'s side of this, bias is [Weak checkers get exploited](#/challenges/weak_checker_exploitation)'s.
- **Prompt-space learning works when it is checked.** A frozen model that keeps a tip only when the tip then solves its problem beats GEPA, RL and memory baselines in most task-and-size conditions ([CORE (Contrastive Reflection)](#/papers/nasvytis2026core "CORE: Contrastive Reflection Enables Rapid Improvements in Reasoning (2026)") §4.3, Tab. 1); stored verified corrections raise text-to-SQL accuracy while stored unchecked majority-vote answers fall below no memory ([Measuring Crystallization in Text-to-SQL](#/papers/wang2026crystallization "From Test-Time Scaling to Reusable Memory: Measuring Crystallization in Text-to-SQL (2026)") §5.1, Tab. 1; §5.3, Tab. 18); context optimization with an insight memory matches RL on one model ([MEMO](#/papers/xie2026memo "MEMO: Memory-Augmented Model Context Optimization for Robust Multi-Turn Multi-Agent LLM Games (2026)") §5 Obs. 1, Tab. 2). In SQL, SQLGovernor's rule base, extended by an LLM from failed queries and admitted by experts, raises EX on BIRD dev over stages of self-learning ([SQLGovernor (Tencent)](#/papers/jiang2025sqlgovernor "SQLGovernor: An LLM-powered SQL Toolkit for Real World Application (2025)") §4.3, §6.4.3, Fig. 7); the paper doesn't say whether the consumed data excludes the evaluated queries. The admission check is [Checking a memory across problems before it is reused](#/challenges/verified_memory).
- **SQL supplies the [certificates](#/glossary/certificate).** A counterexample validated by execution, or a proof, gives a precise gate and new information each round.

**Size of the gain:** step change, our estimate. It is measured as held-out certified accuracy per round of an improvement loop, where compounding means the per-round gain stays above zero past round three. The reason: a system would keep improving without labels or weight training; the estimate is contested, since the listed loops report a one-round plateau and most positive cases train weights (§ What's known).

## Why it's hard
- **A sound gate can stall the loop.** REUSE promoted far fewer changes than the ungated rule it was compared with ([Which Self-Improvements Should We…](#/papers/sun2026reuse "Which Self-Improvements Should We Trust? Reliable Self-Improvement When Agents Reuse Their Benchmarks (2026)") Tab. 1), so a loop may stop compounding because the gate rejects nearly everything.
- **A no-regression gate can lift in-domain without lifting held-out task types:** GRASP's gate, given to five baselines with one proposal per batch, lifted each in-domain and none on held-out task types ([GRASP](#/papers/moll2026grasp "GRASP: Gated Regression-Aware Skill Proposer for Self-Improving LLM Agents (2026)") §4.6, Tab. 5). Gate variants: Statistical acceptance gate.
- **A no-regression gate may block the changes that gain most.** Structural changes can break some solved tasks before they pay off; a step-attributing optimizer gained most where it changed the pipeline (our reading of [FAPO](#/papers/kassianik2026fapo "FAPO: Fully Automated Prompt Optimization of Multi-Step LLM Pipelines (2026)") §4.3, Tab. 2).
- **Headroom shrinks with stronger models:** evolved text-to-SQL prompts gain most for the cheapest model ([RoboPhD](#/papers/borthwick2026robophd "RoboPhD: Self-Improving Text-to-SQL Through Autonomous Agent Evolution (2026)") §4.2, Tab. 1).
- **Prompt-space memory overloads.** Merging many reflections in one call drops specific lessons ([Combee](#/papers/li2026combee "Combee: Scaling Parallel Prompt Learning for Self-Improving LLM Agents (2026)") §2.2, Fig. 2), and whether accumulated memory turns redundant or contradictory is open (App. B).
- **Scaffold gains may not outlast the next model:** for many recent LLM-based software-engineering techniques, one generated prompt sent to a newer model beat the published result ([What Survives the Next Model?](#/papers/salsabil2026survives "What Survives the Next Model? Benchmarking LLM-Based Techniques Against Single-Prompts (2026)") abstract, §V-A).
- **The checker limits the loop.** In SQL, provers cover few realistic pairs ([SQL features that verifiers don't cover](#/challenges/verifier_coverage_gaps)), so certified verdicts come mostly from the easier items.

## Verifiable signal
Held-out certified accuracy after each round, on items never used for selection, with the keep-or-reject rule fixed in advance; compared with an ungated loop and a self-judged one, over five or more rounds and several seeds. The loop compounds when the per-round gain stays above zero, beyond the test's error, past round three. The gate is measured by its false-promotion rate on changes known to be null. In SQL the items and the gate's verdicts are certified by executing counterexamples and by proofs; the statistics are [Comparing LLM methods under noise](#/challenges/method_comparison_under_noise) § Verifiable signal.
