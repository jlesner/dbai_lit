- **[anthem 2.0](https://arxiv.org/pdf/2507.11704 "anthem 2.0: Automated Reasoning for Answer Set Programming (2025)")**: Automated Reasoning for Answer Set Programming (Theory and Practice of Logic Programming 25(4) 2025 (ICLP 2025)). A tool that verifies answer set programs written in mini-gringo, a fragment of the clingo solver's input language with arithmetic and simple choice rules but no aggregates (abstract, §2): it proves strong equivalence (the same stable models inside any larger program), external equivalence (the same output for every input that a "user guide" permits) and adherence to a first-order specification (§4.1–4.3). <span class="links">[🔎](#/papers/fandinno2025anthem "Summary") · [PDF](https://arxiv.org/pdf/2507.11704) · [arXiv](https://arxiv.org/abs/2507.11704) · [DOI](https://doi.org/10.1017/S1471068425100112) · [Code](https://github.com/potassco/anthem)</span> <span class="tags"><a class="tag" href="#/tags/method">method</a><a class="tag" href="#/tags/prove">prove</a><a class="tag sub" href="#/tags/dsl-datalog">dsl-datalog</a></span>
- **[DatalogBench](https://arxiv.org/pdf/2609.37233 "DatalogBench: Evaluating Large Language Models on Text-to-Datalog Synthesis (2026)")**: Evaluating Large Language Models on Text-to-Datalog Synthesis (preprint 2026). A benchmark of text-to-Datalog synthesis in the Soufflé dialect: each task gives a natural-language question and the input and output relation signatures, and a candidate program counts only if it compiles and reproduces the expected output on every held-out evaluation variant (abstract; §3; §5.2). Evaluates LLMs prompted directly, with and without relation descriptions and an input–output example, and coding agents that get execution feedback (abstract; §5.1). <span class="links">[🔎](#/papers/li2026datalogbench "Summary") · [PDF](https://arxiv.org/pdf/2609.37233) · [arXiv](https://arxiv.org/abs/2609.37233) · [Code](https://github.com/ZJU-PL/DatalogBench)</span> <span class="tags"><a class="tag" href="#/tags/benchmark">benchmark</a><a class="tag" href="#/tags/hacking">hacking</a><a class="tag" href="#/tags/harness">harness</a><a class="tag" href="#/tags/labels">labels</a><a class="tag sub" href="#/tags/dsl-datalog">dsl-datalog</a><a class="tag sub" href="#/tags/llm-gen">llm-gen</a><a class="tag sub" href="#/tags/nl2dsl-eval">nl2dsl-eval</a></span>
- **[QLCoder](https://arxiv.org/pdf/2511.08462 "QLCoder: A Query Synthesizer For Static Analysis of Security Vulnerabilities (2026)")**: A Query Synthesizer For Static Analysis of Security Vulnerabilities (ICLR 2026). An agent built on Claude Code that writes a CodeQL static-analysis query from a CVE's metadata; a query counts as successful only if it compiles, reports a dataflow path through the patched code in the vulnerable version, and reports none through it in the fixed version (§3.1); the authors report success for 53.4% of 176 Java CVEs (abstract; Tab. 1). <span class="links">[🔎](#/papers/wang2025qlcoder "Summary") · [PDF](https://arxiv.org/pdf/2511.08462) · [arXiv](https://arxiv.org/abs/2511.08462) · [Code](https://github.com/neuralprogram/qlcoder)</span> <span class="tags"><a class="tag" href="#/tags/code">code</a><a class="tag" href="#/tags/compact">compact</a><a class="tag" href="#/tags/harness">harness</a><a class="tag" href="#/tags/method">method</a><a class="tag" href="#/tags/nl2dsl">nl2dsl</a><a class="tag sub" href="#/tags/dsl-datalog">dsl-datalog</a><a class="tag sub" href="#/tags/llm-gen">llm-gen</a></span>
