# Selection Without Signal, Recovery Through Expression: A Measurement Study of Post-Hoc Falsification Operators for Frozen Small Code Models

## In brief

- Measures whether post-hoc operators over a frozen small code model's own samples (selection, verification, repair, elimination, portfolios, sound vetoes, generation conditioning) beat Best-of-N, which deploys the first candidate that passes the visible tests; correctness is the hidden tests' verdict (abstract; §2). Models of at most 1.7B run locally (Qwen2.5-Coder 1.5B and 0.5B, DeepSeek-Coder 1.3B, Qwen3 probes) on a self-authored benchmark, an engineered one, HumanEval+ and MBPP+ (§3; Tab. 2).
- Every operator runs on the same cached candidate pools at matched compute and is judged against Best-of-N by paired McNemar counts, with a do-no-harm bar fixed in advance (§2; Fig. 2); Prop. 1 gives the number of tasks a zero-harm observation needs before it certifies a harm rate (§2).
- Evidence against selection and repair over a weak model's samples under an execution check, beside [Sample More, Reflect Less](#/papers/mirzaei2026samplemore "Sample More, Reflect Less: Self-Refine and Reflexion Lose to Repeated Sampling at Equal Token Cost, from 1.5B to 7B (2026)"): the author reports that none of 26 operators improves held-out accuracy over Best-of-N on the cells tested (abstract; Tab. 3), explained by a "coverage wall", a "capability scissors" and a "near-empty consensus trap" (abstract; §4), and that the only accuracy gain is a fix to code extraction, outside the model's semantics (abstract; §3, Tab. 4).

## In plain words

Small code models, run locally and never fine-tuned, often write programs that look right but are wrong. A common remedy post-processes the model's own samples: pick one, check, repair or filter them. Motivated by such models' appeal for offline and privacy-constrained use (§1), the author asks whether any such procedure returns a correct program more often than deploying the first sample that passes the visible tests, when both spend the same number of model calls and correctness is judged by hidden tests the procedure never sees (§2). The paper presents itself as "A Measurement Study" (title). Of twenty-six such procedures, none improves accuracy on the hidden tests over that baseline on the models and benchmarks tested (abstract). The only accuracy gain comes from a better code extractor: on the base model DeepSeek-Coder-1.3B it adds 12 solved tasks on HumanEval+ and 33 on MBPP+ (standard Python benchmarks) over the standard extractor, losing none; on two instruction-tuned Qwen models the gain is small and not significant (Tab. 4).

## Background and terms

**Terms to know:** [pass@k](#/glossary/passk) · [McNemar's exact test](#/glossary/mcnemars-exact-test) · [compute-matched comparison](#/glossary/compute-matched-comparison) · [metamorphic testing](#/glossary/metamorphic-testing) · [statistical power](#/glossary/statistical-power) · [self-consistency (majority voting)](#/glossary/self-consistency-majority-voting)

**The paper's own terms:**
- **Frozen small code model**: "at most about 1.5 billion parameters and run locally without fine-tuning" (abstract).
- **Public (visible) and hidden tests**: a program public-passes when it passes every public test and is correct when it passes every hidden test; on HumanEval+ and MBPP+ (EvalPlus's augmented Python benchmarks, [EvalPlus](#/papers/liu2023evalplus "Is Your Code Generated by ChatGPT Really Correct? Rigorous Evaluation of Large Language Models for Code Generation (2023)")) public tests are the EvalPlus base suite and hidden ones its augmented plus suite (§2 "Formal setup").
- **Post-hoc operator**: reads the prompt, public tests and pool (the sampled candidates, shared by all operators) and returns one program; leakage-free if it never reads hidden tests or a reference solution, matched-compute if it makes as many model calls as the baseline (§2).
- **BoN (Best-of-N)**: the first public-passer in pool order, with a fallback when none passes (§2); in the glossary's terms, [best-of-N sampling](#/glossary/best-of-n-sampling) scored by the public tests.
- **Harm b10, gain b01, do-no-harm bar**: tasks BoN solves and the operator fails, and the reverse; the bar is zero harm, "fixed before the deciding runs", and a gain is judged by the one-sided exact McNemar test plus a stricter net-gain floor of 6 declared in advance (§2).
- **Semantic output-space operator**: one acting on code meaning, execution behaviour, repair traces or learned correctness features; all twenty-six surveyed operators are of this kind (Def. 1).
- **Sound**: of a relation, selector or veto, never refuting a correct program (§3; §2.1, #5); a sound veto overrides the largest fingerprint cluster only if it cleanly violates a sound metamorphic relation and a clean alternative cluster exists (§2.1, #17).
- **Consensus trap**: a task whose public-passing majority is hidden-wrong while some pool candidate is hidden-correct (Def. 2).
- **Execution fingerprint**: a candidate's outputs, or markers such as an error or timeout, on at most 24 probe inputs built from public-test arguments and type-aware mutations (§2.1).
- **Cell**: a model under test ("model cells", §3 setup), or a model–benchmark pair ("all six cells", §3, before Tab. 6).

**Missing glossary terms:**
- **Learn-then-Test (Hoeffding–Bentkus bound)**: a distribution-free method (Angelopoulos et al., 2021) that turns an observed harm rate on n examples into a p-value against the claim that the true rate exceeds a target α; a certificate issues when it is at most a level δ (§2.1, Eq. 1; α = 0.05, δ = 0.10, Tab. 1).
- **Severe test (Popperian falsification)**: a test a claim "would probably have failed were it false" (§1); in its most principled form an operator attacks each candidate with one and keeps what survives (abstract).

**Builds on:**
- İşcan (2026), the author's companion study, where naming severe tests in a coding agent's prompt did not help beyond a labels-only control; this paper is "that successor" (§1).
- Selection by execution agreement or model-written tests: MBR-Exec (Shi et al., 2022) and CodeT ([CodeT](#/papers/chen2022codet "CodeT: Code Generation with Generated Tests (2023)")) (§1; Tab. 7).
- Self-repair from execution traces or self-critique: Self-Debug ([Self-Debugging](#/papers/chen2023selfdebug "Teaching Large Language Models to Self-Debug (2023)")), Self-Refine, Reflexion ([Reflexion](#/papers/shinn2023reflexion "Reflexion: Language Agents with Verbal Reinforcement Learning (2023)")) (§1; Tab. 7).
- Damani et al. (2025), whose finding that online difficulty-adaptive allocation on code can fall below best-of-k the paper reproduces (§4; Tab. 7).

## Problem and setting

- **Question:** does any executable post-hoc falsification operator make a frozen small model write more correct code (§1), against BoN at matched compute (§2)?
- **Models:** Qwen2.5-Coder-1.5B and -0.5B (instruction-tuned), DeepSeek-Coder-1.3B (base), and Qwen3-0.6B/1.7B on selected probes (§3; Tab. 4 caption). Pools: 8 samples at temperature 0.8 (§3).
- **Benchmarks** (Tab. 2): self-authored FALSIFY-BENCH-local (52–80 tasks, 7 families); Substrate-W (32 tasks engineered so a sound metamorphic relation could select correctly); HumanEval+ (164) and MBPP+ (370 of 378 kept), used because a self-authored benchmark "is treated as suspect" (§1).
- **Protocol:** each operator's claim, placebo or fair baseline, and confound check were fixed in advance (§3; Fig. 2).

## Approach

- **The survey** (§2.1; Tab. 8): twenty-six operators in families: refute-first prompting, selection, verification, repair, elimination and vetoes, generation conditioning, compute allocation.
- **M1, expression-layer recovery** (Alg. 1): only on tasks with no standard public-passer, re-extract a single function robustly (prose stripped, broken code fences tolerated), rename it to the most-called name in the public tests' assertions, and deploy it if it now public-passes. It reads no hidden test and adds no generation.
- **ACE, adaptive consensus early-stop** (Alg. 2): sample one candidate at a time, cluster public-passers by fingerprint, and stop once the largest cluster has an unbeatable lead or reaches a threshold τ while leading. Harm, against the full-budget consensus pick, is bounded by Learn-then-Test.
- **Prop. 1** (§2): how many tasks a zero-harm observation needs before it can certify, distribution-free, that the true harm rate is at most α. With harm a Bernoulli event of unknown rate, zero harm in n independent trials, and the exact one-sided upper confidence bound at level δ, it needs n ≥ ⌈log δ / log(1 − α)⌉: 45 at α = 0.05, δ = 0.10. Corollary 1: a zero-harm result on at most 32 tasks is under-powered; no distribution-free Hoeffding–Bentkus certificate can issue.
- **Lemma 1** (§2.1): a leakage-free selector that returns a public-passer, under a majority-symmetry assumption (where the public-passing majority is hidden-correct, deviating from it does not raise expected accuracy), can net-gain over BoN only on consensus-trap tasks, with expected net gain at most the trap's probability; "a diagnostic lemma, not a general impossibility theorem" (§2.1).

## Results

- **Survey:** each of the twenty-six is null, negative, falsified or weak against BoN at matched compute, and none clears both the zero-harm and significance bars (Tab. 3; Tab. 8). Apparent gains broke under confound checks (§3). An execution-behaviour signal detects hidden failure above chance but changes no deployed pick (§3).
- **Coverage wall** (hard-task failures are systematic, §1): for the weak model, at 16 samples on 30 held-out hard tasks, 16 still have no hidden-correct candidate (§4).
- **Capability scissors** (a competent generator leaves almost no detectable error among public-passers, §1): among Qwen2.5-Coder-1.5B's public-passers, the hidden-correctness signal in code-embedding and wavelet features (multi-scale transforms of the code as a signal, §2.1) is at chance; enabling reasoning on a stronger model raises pass@1 but lowers this falsification signal (§4).
- **Near-empty consensus trap:** on two benchmarks engineered to admit a sound veto, with Qwen2.5-Coder-1.5B, a consensus-majority trap occurred in 0 of 26 opportunities (§4).
- **External selection** (Tab. 6): headroom ("the most a perfect selector among visible-passers could gain", §3) is zero on HumanEval+ with DeepSeek; on the other five cells, with headroom of 6–17 tasks, a leakage-free consensus selector (agreement among public-passers) gains at most net +3, never significant (two-sided p ≥ 0.25).
- **M1** (Tab. 4; Fig. 4): DeepSeek-Coder-1.3B goes 29 → 41 on HumanEval+ (+12, one-sided p = 2.4 × 10⁻⁴) and 128 → 161 on MBPP+ (+33), with zero harm; Qwen cells +1 to +4, not significant.
- **ACE** (Tab. 5; Fig. 3; Qwen2.5-Coder-1.5B, local benchmark): the first zero-harm threshold, τ = 4, saves 19.1% of samples (bound p = 0.0165); τ = 1 saves 63.9% with harm 2 and misses the bound. The saving collapses on DeepSeek, and reinvesting freed samples on hard tasks is null (§3).

## Limits the authors state

- "It is not shown that falsification is useless, nor that post-hoc operators never help"; the claim covers frozen small code models on the benchmarks tested (§4).
- External replication spans 0.5–1.5B models in two families, and a third family would strengthen it; a third external benchmark remains worthwhile, but LiveCodeBench, a code benchmark, is deferred: it ships no canonical solution and would need invasive grader changes (§4).
- Several verdicts rest on benchmarks of at most 32–80 tasks where no do-no-harm certificate can issue, and are marked suggestive (§4).
- "twenty-six operators is a survey, not a census": logit- or entropy-based uncertainty and training-based generator changes were not exhaustively tested (§4).
- Scoring is by hidden unit tests only, with no claim about code quality or abstention usefulness (§4).
- Ollama (the local model server) outputs are not byte-identical across hardware, drivers or versions, so task-level discordances "could shift by one or two on a different machine" (§4).
- ACE's threshold is chosen on the evaluation set without correction, so its bound holds at that one operating point; against a deployment that stops at the first public-passer "the saving falls toward zero" (§3).
- M1 "does not synthesize new logic, and on the weak cell it is bounded by the coverage wall" (§3).

## Open problems and building blocks

- **Open:** a coverage-increasing intervention (a stronger generator, or retrieval adding new correct candidates) would move the coverage wall, and a weaker visible-test filter would refill the consensus trap: "both deserve a direct test" (§5).
- **Released:** per-operator numbers and falsification logs in "the released manifests" (Tab. 3 caption; App. A).
- **To reuse it:** models served through Ollama on one 6 GB consumer GPU (§3); M1 needs public tests whose assertions call the target function (Alg. 1); ACE's bound needs at least 45 tasks (§2.1).
- **Beyond its domain:** of M1, "Its lesson generalizes beyond this paper": for a weak frozen model a measurable share of failure is expression, not logic, so the extraction harness should be fixed first (§3).
